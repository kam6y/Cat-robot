# Gemma 4 E2Bを標準にしたCat Robot

## 実装範囲

ブランチ `feature/gemma4-conversation`。main `d3db63e` に実機推論プローブ `b14562d` を追加した状態から分岐し、実際のアプリ構成をGemmaへ接続した。mainと元の検証ブランチは変更していない。

`ConversationDependencies.live()` は、共通インターフェース `ReplyGenerating` / `AddressClassifying` / `ModelAvailabilityChecking` に同じ `GemmaConversationService` を渡す。Apple Intelligenceの利用可否を起動条件にしない。既存のAFM実装とそのテストは変更せず保全している。モデル選択UI・自動AFMフォールバックは設けない。

猫の画面、音声認識、読み上げ、会話ライフサイクルは既存のまま。Gemmaの差分出力はサービス内で累積テキストへ変換する。返答は履歴を維持し、宛先判定には都度独立したセッションを作る。重い推論エンジンは共有する。

- LiteRT-LM 0.17.1、GPU、8,192トークン、返答上限160トークン、thinking無効。
- モデルは[前回の実機検証](2026-09-21-gemma4-e2b-device-test.md)と同じ固定ファイル。アプリ初回ロード時にサイズとSHA-256を検証する。
- 未配置・破損・起動失敗をGemma用の表示で知らせる。
- 履歴トークン数と入力・システム指示のUTF-8バイト数、出力予算、区切り余白を合計して上限を検査する。保守的なため実際の8Kより早く上限となり得る。既存の会話リセットと再入力案内を利用する。
- キャンセル後のネイティブ推論終了を待ち、直後の再開も受け付ける。キャンセルされた会話セッションは再利用しない。終了とキャンセルの競合をロック内で確定する。

## 実機で確認できたこと

iPhone 16 Pro / iOS 27.2（24B5084k）、Xcode 27.0（27A266a）。`scripts/run_gemma_app_test.sh` によるビルド・テスト・結果回収まで成功した。実機テスト1件成功、失敗・スキップなし。

製品と同じ `ConversationDependencies.live()` と `ConversationViewModel` を使い、推論と読み上げを実サービスで実行した。

| 確認内容 | 結果 |
| --- | --- |
| 猫への呼びかけ、AIへの明示質問 | addressed |
| お母さん・先生への発話、明示的な独り言 | notAddressed |
| 宛先不明の「明日は晴れるかな」 | ambiguous |
| 麦茶→ほうじ茶への好み訂正と再質問 | 「ほうじ茶がお好きなんですよ。」 |
| 文字入力→返答字幕→実際の読み上げ完了 | 3往復成功 |
| 一時停止後の文字入力再開 | 「おかえりなさい。」 |
| 長い入力の推論途中で停止し、直後に文字入力 | 「ただいま。」、modelBusyエラーなし |
| 部分出力後のリセットと次の生成 | 「こんにちは。」 |

3往復の完了時間は約6.57秒・5.89秒・3.49秒。実際の読み上げ完了まで含むため、推論単体の返答開始時間とは比較しない。

宛先判定は小さな6例のスモークテスト。最初は家族への発話を誤判定したため、猫以外の宛先を優先し、疑問文だけでは猫宛てと断定しない分類指示へ修正した。広い会話での精度を保証する結果ではない。

## 再実行と手動確認

[READMEのGemma準備手順](../../README.md#gemmaモデルの準備)に従う。実機のモデルが配置済みなら以下だけで実行できる。

```bash
scripts/run_gemma_app_test.sh '<iPhone UDID>'
```

`GemmaAppDeviceTests` schemeのみが結合テストを有効にする。通常の `CatRobot` schemeでは実機推論テストをスキップする。合成プロンプトだけを使い、テスト中は実際に読み上げる。

検証後に同じビルドを実機へインストールして通常起動した。アプリで「会話を始める」→「猫ちゃん、こんにちは」と話すと、既存の音声経路からGemmaを使える。文字入力でも試せる。

今回の自動結合テストは文字入力・分類・返答・実際の読み上げ・ViewModelの一時停止まで。人がマイクに話す音声認識からの一連の聞き取り、実画面の操作・見た目、長時間の発熱と電池消費は未検証。自動モデルダウンロード、永続記憶、tool calling、16K/32K設定は実装範囲外。初回のモデル転送経路は別途未検証で、今回は既に配置された検証済みモデルを使った。
