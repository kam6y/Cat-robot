# Supertonic通常アプリ統合の実機検証

2026-09-26、`feature/supertonic-voice-integration`。main起点は`7e8c9b0`、実機比較のビルドは`472aa3e4500165ed668a0cd1bd3a2bbb0664f3d2`。

## 実装

- 通常アプリの音声はSupertonic 3。F1を初期値とし、F1〜F5/M1〜M5を選択・保存する。
- 設定を開く際は会話を停止し、閉じても自動再開しない。会話記憶は変更しない。
- iPhone/Bluetoothの読み補正は合成入力だけに適用。字幕と記憶は原文。URL・メール・コード・識別子内は保護する。
- 文ごとの直列合成と一文先読みを実装。先読みは再生中の一文に加え次の一文だけを保持し、ネイティブ推論を同時実行しない。停止時は推論終了を待ち、古いPCMを破棄する。
- 比較完了まで製品の再生方式は既存のfirstSentenceを維持する。Appleの実装は保全し、自動フォールバックはしない。

## 測定条件

iPhone 16 Pro (`iPhone17,1`)、iOS 27.2、USB接続。固定のSupertonic 3 / ONNX Runtime 1.24.2、日本語、F1、CPU 2 threads、8 steps、speed 1.05。全10声試験だけ声を変更する。Gemmaは通常と同じGPU/12K/返答160トークン、試験専用の空メモリを使用し、利用者の記憶を変更しない。

時刻は単調時計とPCM再生コールバックによる。開始はrequestから最初のspeechStarted、文間は前のspeechFinishedから次のspeechStarted、合計はrequestからfinished。外部録音による音響計測ではなく、モデルが音声内に含める無音は文間値に含まれない。firstSentenceの後半は複数文をまとめて合成するため、その内部文間も計測対象外。

fixedは同じ6文章×3方式×3反復=54試行、反復ごとに方式順を回転する。Gemmaは6プロンプト×2方式×3反復=36試行で生成文差があるためfixedと混ぜない。serious/criticalのときは試行前に冷却し、その待機も記録する。p95はnearest-rank。

- 検証済み比較ブランチの音声エンジンは書き直さず移植した。新しい構成のテストで接続を確認したが、再実装による独立検証ではない。

## 独立レビュー

新しい文脈の独立レビューでCritical 0 / Important 2 / Minor 0。以下の2件を、修正前に失敗する回帰テストと修正後の全体試験で確認した（`68851f7`）。

1. 文キューが満杯の間も生成失敗を検知できるよう、上流の読み取りを送信待ちから分離。累積snapshotは最新1件だけを保持し、全文2,000文字を上限とする。置き換わるsnapshotに過去の本文が含まれるため、文そのものは落とさない。8文の欠落・重複と失敗時の即時停止を検証した。
2. 大文字・大小混在HTTPスキームも文分割で保護し、URLのクエリが分割後に読み補正される不具合を修正した。

コード完成後、長時間の実機比較と独立レビューを並行させた。最終の方式選択は主担当が実機結果に基づいて行う。レビュー後の修正は回帰テストと全体試験で確認し、修正版でも実機測定を行う。
