# 聞き取り表示・ハード表記・校正画面の調整

2026-10-27。基点 `1d9e1d0` から製品・試験コミット `f85f74e` までを検証した。作業ブランチは `feature/ui-reorganization`。

## 変更

- 会話画面の左上に「聞き取り中」チップを追加した。聞き取りが終わると消え、待機中や会話を阻む記憶状態では表示しない。
- 接続状態・設定・校正・権限説明・アクセシビリティの静的な利用者向け表記を「ハード」に統一した。
- 「中立と回転方向を調整」を設定と同じ構成にした。標準文字では左の項目列と右の調整画面、大きい文字では項目一覧から詳細へ進む。「中立の調整」「回転方向」「動作確認」を切り替えても、同じ校正セッションと変更値を保つ。

Codex が聞き取りチップ・用語・検証を担当し、実際の Claude Code が校正画面とその操作試験を担当した。互いの変更を確認し、Codex がビルド・試験・コミットを直列で実行した。[Claude の作業記録](ui-polish-2026-10-27/claude-pair-summary.md)。

## 検証結果

全体 XCTest は **839件、成功837件、スキップ2件、失敗0件**。iPhone 18 Pro / iOS 27.0 Simulator で実行し、223ファイルのハッシュが試験前後・独立レビュー・コミットの内容で一致した。スキップは人の操作を必要とする `RobotMotionIntegrationDeviceTests.testSelectedStage` と `SupertonicIntegrationDeviceTests.testSelectedStage`。

- 聞き取りチップの状態遷移、左右の safe area を変えた左上位置、メニューとの分離を確認した。文字入力時は画面を100pt高くすると顔も100pt高くなり、チップと入力欄に重ならないことを検証した。
- 校正の3項目間で変更値・選択を維持し、標準文字と最大アクセシビリティ文字サイズの往復でもセッションを維持する。
- 大きい文字の設定から校正詳細まで開く経路、停止ボタン、一覧への戻り、未保存の変更に対する確認と取消、校正終了後の設定への復帰を実際の SwiftUI 画面操作で確認した。
- 標準文字の最大サイズで長い切断メッセージを表示しても、調整領域と保存操作を利用できる。切断時の無効化条件も保持した。

追加試験は実装前に失敗を確認した。実装後、重複するスライダーの読み上げラベル、カテゴリ選択、文字サイズ変更時の表示を調整した。確認ダイアログの取得失敗は変更前の製品でも発生しており、特定の表示コンテナだけを根因とは断定しない。複数の修正と fixture の後片付けを入れ、待ち時間を延長せずに最終試験を通過した。

## レビューと判断

[独立レビュー](ui-polish-2026-10-27/codex-review.md)は Critical 0、Important 0。レビュー時点では全体試験が進行中だったが、その後、同一ソースで上記の成功を確認した。

任意の追加試験が1件ある。短い画面で「聞き取り中・再接続・熱警告」と文字入力を同時表示する組合せを、既存の複数チップ試験へ追加する提案は保留した。複数チップの共通配置と聞き取りチップ単体の試験は通過しており、製品の不具合は確認されていない。

文字入力中の顔は、チップと入力欄を除いた残りの高さを使う仕様を維持した。チップの領域を常時予約する案は採用していない。そのため、聞き取り状態の切替で顔の高さが変わる場合がある。入力欄の位置と通常画面の顔85%枠は維持する。

実機のBLE動作・保存・停止の時間、日本語IME、VoiceOverの実音声はこのSimulator試験から結論づけない。ジェスチャー名やモデルへの動作説明に含まれる「首」は変更対象外。既存の横画面向けUIを調整し、iPad・縦画面の再設計や無関係な既存サブシステムの監査には範囲を広げていない。[判断と検証範囲の記録](ui-polish-2026-10-27/execution-ledger.md)。
