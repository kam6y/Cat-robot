| 判断 | 理由と、判断が合わなかった場合の影響 |
|---|---|
| Claudeの実装・比較subagentと、親の会話統合を並行する | 利用者の明示指示に従い所有ファイルを分けた。取りこぼしは統合ビルド・全体試験で確認する |
| 写真の外装・背景・反射は比較から除外する | 顔のベクター要素を比較するため。写真全体の画素一致は保証しない |
| 各機能の試験、全体試験、最後の描画差分試験を実行する | 同じ合格済み範囲の無条件な再実行を避ける。最終差分に非描画の変更があれば全体の再確認が必要 |
| Claudeの実装範囲を描画3ファイル・描画試験・比較ハーネスに限定する | 親が統合を担当して同時編集を防ぐ。担当漏れはビルドとレビューで検出する |
| 反復はMacハーネス、受入用の静止画像はiOS XCTestで作る | Simulatorの並行ビルドを避ける。プラットフォームの描画差は最終iOS画像で確認する |
| 開口はクリーム色の輪郭と暗い内部で描く | 黒背景でも口が読めるようにする。舌・牙は加えず、見た目の好みが異なれば形と配色の調整が必要 |
| 比較は高さを合わせて等比変換し、横の黒い余白を切り落とす | 写真の画面比率と固定fixtureの比率が異なるため。縦横を別々に伸縮せず、顔の比率を保つ |
| Reduce Motion・非active時は表情と口の補間も止める | 設計の静的表示要件を優先する。口の切り替えは滑らかな遷移ではなく即時になる |
| 目・ひげの外接矩形の重なりを、形そのものの交差へ置き換える | 曲線の外接矩形は意図せず重なるため。鼻と口の接点は許し、目とひげ等の不要な交差だけを検査する |
| パスの交差はCoreGraphics APIを使う | macOS上でSwiftUI Pathの交差結果に差があったため。独自の幾何判定エンジンを増やさず、iOSでも同じ判断を試験する |
| 視覚比較の修正回数に上限を置かない | 利用者の「相違点がなくなるまで」の指示を優先する。追加の確認時間がかかる |
| 表情の可視性をカメラ・首・会話開始済みフラグから独立させる | 文字入力や復旧画面でも顔を表示するため。会話画面がactiveで設定が閉じていれば自動表情が表示される |
| happyのひげをneutralと同じにする | 採用画像の差が1px以内だったため、初期仕様の微小な持ち上げより画像を優先した。持ち上げが必要ならプリセットを再調整する |
| 共有する型・生成projectを含め初期実装を一つのコミットにまとめる | 独立した作業を統合し、途中のビルド不能なコミットを避ける。レビュー差分は大きくなる。続く描画修正は独立したコミットにした |
| 全体コードレビューを同じ独立レビュアーの複数部分に分ける | 描画反復中に会話部分を確認し、最後に固定した描画差分を確認する。最後のソース範囲と差分を明示して取りこぼしを防ぐ |
| 写真の約1.5〜4pxの右寄りをコピーせず左右対称を保つ | 生成画像の微小な位置ずれとして扱った。写真の位置を文字どおり再現する要求とは差が残る |
| 実機の動的挙動を静止画像で合格としない | まばたき・補間・キーボード・実音声との同期は、別途実機確認が必要。端末固有の問題が後から判明する可能性がある |
| 瞳のカメラ追従・端末内ツールを別課題にする | 承認済み計画の範囲を維持する。視線はプリセット、fallbackは従来の自動表情のままで、それらの追加機能は提供しない |
| 目の帯の末端の修正を9表情共通の既定値へ反映する | 表情の切り替えだけで帯の尾が伸び縮みするのを避ける。採用画像がない派生表情にも同じ細り方が適用される |

| 反復中の画像と最終キャプチャをすべて保存する | 各回の指摘と画像・出所の対応を残すため。553ファイル、非圧縮で約111 MB分の履歴が増える |
