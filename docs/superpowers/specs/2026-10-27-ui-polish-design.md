# UI調整: 聞き取り表示・ハード表記・校正画面

2026-10-27。利用者の依頼: 聞き取り中のチップを左上に表示し、UIで「首」と呼ぶ対象を「ハード」に統一し、「中立と回転方向を調整」を設定画面と同じ構成にする。

## 方針

- 会話画面は既存の左上チップ配置を使う。phase が listening で、待機中でも会話を阻む記憶状態でもないとき「聞き取り中」（マイク）を先頭に表示する。発話・処理・停止中には出さない。通常の顔85%枠、入力欄の同一性、他チップの条件は保つ。文字入力時の顔は、チップ行と入力欄を除いた残りの高さを使う。
- 接続状態、設定、校正、権限説明、アクセシビリティの利用者向け表示にある「首」を「ハード」に置き換える。コード識別子・通信形式・動作名（首を振るなどのジェスチャー）と過去の検証記録は対象外。
- 校正は既存設定と同じ左の項目選択、右の調整内容にする。標準文字では左220pt、右にスクロールできるForm。大きい文字では項目一覧から詳細へ進む。
- 分割は「中立の調整」「回転方向」「動作確認」。初期は中立。調整値・反転・確認移動は既存のsessionへ接続する。保存状態と保存/変更を戻す操作はどの項目でもアクセスできる。
- 画面を開いている間は停止と校正終了操作を利用できる。項目の切替では校正を終了しない。大きい文字の詳細は専用の「調整項目へ戻る」で一覧へ戻し、校正終了はルートの確認を経由する。未保存の変更を捨てる前の確認、親設定の完了・シートdismiss禁止、接続切れのdisabled条件を維持する。
- 文字サイズが変わっても同じsessionとdraftを保持する。

## 選択した構成

既存の長い1画面の見た目だけを整える案と、設定と同じ項目別構成を比較し、後者を採用する。利用者が指定した「設定と同じ」の構成に合い、調整目的を選んで操作できる。画面分割や保存領域の細部は実装担当の判断とする。

## 検証

聞き取り表示の状態遷移、左上配置とメニュー・入力欄への非重複、校正項目の切替とdraft維持、最大文字での操作、戻る確認と停止の到達性を確認する。Bluetooth実機動作と日本語キーボードの手動試験はこの作業に含めない。
