# jpreprocessによる日本語読み上げ補正

日付: 2026-10-28
状態: ユーザーが「完全に置き換えちゃっていいよ」と承認。従来の2語置換と、それへ戻す経路を廃止する。実装時の検証結果と未確認事項は [検証記録](../../validation/2026-10-28-jpreprocess-pronunciation.md) を参照。

## 目的と範囲

`+`を意図しない音で読む、YouTubeのような英語名を自然な日本語で読めない、といったSupertonicの読み違いを減らす。単語を一つずつ手作業で登録することを主な解決方法にせず、jpreprocessの日本語辞書と読み推定を利用する。

音声合成の前に、読める部分を日本語の発音表記へ変換する。Supertonicの声・モデル・言語設定は既存のまま使う。処理はiPhone内で完結し、返答の表示、アクセシビリティ用の原文、会話履歴には元の文章を使う。

すべての固有名詞・数式・曖昧な漢字の読みを正解にすることや、アクセントを指定することは今回の目標に含めない。辞書編集画面、音声エンジンの交換、クラウド処理も追加しない。未知語の削除、発話の切り捨て、キャンセル後の再生、メインスレッドでの辞書解析は避ける。

## 検討した方法とユーザーの選択

| 方法 | 利点 | このアプリでの負担・限界 |
| --- | --- | --- |
| Swiftの置換規則を拡充 | 現在の構成を小さく拡張できる | 英語名・固有名詞の登録と保守が増える |
| NeMo等の日本語テキスト正規化 | 記号・数字の規則を参考にできる | それだけではYouTube等の読み辞書を補えず、iOS向けの移植も必要 |
| jpreprocessと日本語辞書 | 単語の読みと数字・助数詞等の処理を再利用できる | Rustとの接続、辞書の同梱、Supertonicに渡す文字表現の検証が必要 |

ユーザーの「jpreprocessにしよう」を採用方針とする。続く「完全に置き換えちゃっていいよ」により、旧2語置換は残さず、変換サービスを一本化する。ネイティブ接続と未知語の保持方法の細部は実装側で決める。

## 現在の処理と変更点

`SupertonicSentenceSpeaker.nextPrepared`は1文を受け取り、同期の`SpeechPronunciationNormalizer`でiPhoneとBluetoothを置換してから合成する。通常発話とストリーミング発話はこの経路を共有し、合成は同時に1文、先読みは次の1文までである。

`SupertonicEngine`は文字列を日本語としてモデルへ渡す。入力上限は2,000文字、PCM上限は60秒である。上流の前処理は記号の一部を除去するため、読みを決める処理はその前に置く。jpreprocessの音素列やfull-context labelをSupertonicへ直接渡さない。

変更は、読み変換の非同期サービス、Rustの薄い接続層、辞書・ライセンス資産、プロジェクト生成と検証、関連テストに限定する。既存の音声イベント、文番号、発話の順序と先読み上限を維持する。

## ネイティブ接続と資産管理

- jpreprocess `0.15.0`を正確なバージョンで固定し、`Cargo.lock`とRustツールチェーン指定を管理する。辞書の暗黙ダウンロードを行うfeatureは使わず、同じリリースの配布済み辞書を明示的に読み込む。
- Rustの小さな`staticlib`からC ABIを公開し、iPhone arm64およびSimulator arm64/x86_64の静的XCFrameworkを作る。Swiftからは生成したヘッダーとmodule mapで利用する。プロジェクト生成スクリプトがXCFrameworkを静的リンクし、実行時に別ライブラリをダウンロードしない。
- C ABIの操作は、辞書を指定した作成、1区間の読み変換、結果の解放、インスタンスの破棄に絞る。UTF-8の長さと所有権、失敗ステータスを明示する。Rust panicをFFI境界から外へ出さず、通常の失敗として扱う。文字列中のNUL、不正な出力、変換自体の失敗は音声合成エラーとして通知する。未知語の原文保持は正常な変換結果として返す。
- ソース、ヘッダー、ビルド・取得スクリプト、資産manifest、ライセンスと出典を追跡する。XCFrameworkと辞書本体は既存の`LocalAssets`配下に生成し、Gitへ大型バイナリを入れない。再現可能な取得・ビルド手順をREADMEに記載する。
- 辞書の取得は`v0.15.0/naist-jdic-jpreprocess.tar.gz`を固定する。公式リリースAPIで確認したアーカイブのSHA-256は`8a930bbc57bf4adcf521d53544c7dc9ab8ab3aa997a591b1b1608dc5539017b8`。アーカイブは28,668,638 bytesであり、展開後サイズや実行時メモリ量を意味しない。展開先を検査し、必要な各ファイルのハッシュもmanifestに記録する。
- 通常のXcodeビルドではネットワーク取得・Rustコンパイルを行わず、準備済み資産を検証して使う。欠損・不一致はビルド時に明確なエラーにする。実行時の初期化エラーは既存の音声エラー経路へ伝える。
- jpreprocessおよび配布辞書に含まれる著作権表示・ライセンスを同梱する。依存クレートの通知も固定した依存関係から確認する。

## 音声用文字列を作る規則

通常の文章では、辞書で読みが得られる区間全体をカタカナの発音表記へ変換する。辞書にある英語名だけを拾う実装にはしない。ただし、全文を無条件に変換して未知語を落とすことはしない。

1. URL、メールアドレス、バッククォートで囲まれたコードは現在の保護範囲を引き継ぎ、その内容を変換しない。改行、空白、文末・読点・引用括弧などの区切りも元の文字で保持する。`…`、`・`、`〜`、`♪`、`=`など一般的な記号は区切りとして保持し、前後の既知区間の補正を続ける。未知の絵文字・結合文字を無理に分割しない。数字の中の小数点・桁区切りは機械的に分断しない。
2. 保護されていない`YouTube`/`YouTuber`の大文字・小文字違いは、既存のASCII単語境界と同等の境界で辞書の標準表記へ揃える。既存iPhone/Bluetoothの表記揺れの扱いも維持する。部分文字列として別の識別子に含まれる名前は置換しない。大量の独自語彙は追加しない。
3. 単独の演算子・ボタン記号としての`+`と`＋`は「プラス」を使う。`1+2`も「1プラス2」の意味でよい。辞書にある`C++`などを先に一語として扱い、内部の`+`を壊さない。`+`を含む英字語を辞書で引き、一語の既知語の場合だけその字句を保持する。`Disney+`、`A+`、`x+1`のように分かれる場合の`+`は「プラス」にする。URL・メール・コード内や未知の英数字識別子に属する記号は保護する。複雑な数式の構文解析は行わない。
4. その他は`text_to_njd`による解析結果を検査し、安全に変換できる連続区間に`NJD.preprocess()`を適用する。数字・助数詞・助詞の変化を反映した`get_pron().to_pure_string()`相当のカナを使い、無声化記号・アクセント記号・音素記号をモデル入力へ漏らさない。
5. 解析前後の対応を検査する。正規化済み入力と解析前ノードの表層を対応付けられない場合、未解釈の文字がある場合、解析前に空の読みがある場合は、その区間を元の文字列に戻す。安全な区間を読みへ変換した後に空・不正な出力が生じる場合は、規則6と同様に音声エラーにする。未知語を含む区間全体を戻す保守的な実装を許容し、無理な部分復元はしない。対応付ける前に`NJD.preprocess()`を呼び、未知ノードを消してしまう実装は禁止する。
6. 入力または結合後の出力が2,000文字を超える、非空の入力に対して出力が空になる、といった場合は既存の音声エラー経路へ伝える。上限を超えた文を旧処理や未変換の全文で合成し直さない。新しい分割再生やPCMの連結は導入せず、切り捨てない。

ここでの「原文保持」はjpreprocess層で情報を失わないという契約である。URL・未知語をSupertonicが必ず正しく発音することや、既存の上流前処理がすべての記号を保持することを保証するものではない。

## 実行、失敗、キャンセル

専用のactorが辞書インスタンスを1つ保持し、読み変換を直列に実行する。辞書は初回準備時に一度ロードし、文ごとに読み直さない。通常のspeaker初期化では本物のサービスを渡し、単体テストでは軽い非同期変換関数を注入できるようにする。

辞書準備はspeakerの既存`prepare`経路から行い、`prepare`を経由しない呼び出しにも同じサービスの冪等な準備を使う。初期化に失敗した場合は失敗状態を保持して既存の音声エラー経路へ伝え、各文でロードを繰り返さない。アプリの再起動では再試行できる。旧処理へ戻る経路と旧`SpeechPronunciationNormalizer`を削除し、既存のエラー表示を使う。

`nextPrepared`は変換の前後でキャンセルを確認し、変換が終わってもキャンセル済みなら合成・再生へ進まない。FFI内部は同期であるため実行途中の強制中断は約束しない。1文の入力上限と直列実行で処理量を制限する。取消エラーを握りつぶさない。

`onInput`には元の文と実際に合成する文字列を渡す。診断には使用した辞書版、変換・原文保持・エラーの種類、処理時間を追加できるが、本変更による会話本文の外部送信は行わない。

## 検証と完了条件

実装前に期待値を固定した回帰ケースを作り、Rustの実辞書テスト、Swiftの接続・失敗経路テスト、既存の発話テストを分けて検証する。すべての既存テストに大きな辞書をロードさせない。

| ケース | 確認すること |
| --- | --- |
| `YouTubeを見よう。`、`youtube`、`YOUTUBE`、`YouTuber` | ユーチューブ／ユーチューバーとなり、続く日本語も欠落しない |
| `+ボタンを押してね。`、`＋ボタン`、`1+2は3だよ。` | `+`を意図した「プラス」として渡す |
| `C++`、URL、メール、コード、英数字の識別子 | 語の内部・保護範囲を壊さない |
| iPhone、Bluetoothとその大小文字違い | 既存の補正と境界条件を維持する |
| 数字・助数詞・小数・%、助詞を含む通常文 | 具体例の読みを固定して、jpreprocessの処理が使われることを検証する |
| 未知の英語・漢字、絵文字、結合文字、空白・句読点 | 変換層で原文の一部が黙って消えない |
| 辞書エラー、FFIエラー、空出力、2,000文字超への展開 | 音声エラーとなり、旧処理で合成・切り捨て・重複発話をしない |
| 変換中の停止、次文の先読み、合成失敗 | 取消後に合成・再生せず、文番号と完了イベントの契約を維持する |

プロジェクト生成の決定性・契約テスト、必要なSwiftテスト、Rustテスト、Simulatorビルド、署名したiPhoneビルドを確認する。実機へ反映できる状態ならインストールと起動まで行う。接続できない場合は、実機確認が未実施であることを分けて報告する。

同じSupertonicの声・設定で、旧入力と新入力の短い音声比較を残す。対象は`+`、YouTube、数字・助数詞、普段の自然な返答。文字列テストの成功だけで発音や自然さの改善を断言しない。音声を聴いて確認できない項目は未確認として記録する。

初回辞書ロード時間、通常の短文変換時間、辞書・アプリサイズ増分、実機のメモリ増分を測定する。性能の数値は未測定なので現時点では保証しない。通常の会話で目立つ待ち時間や強制終了を生む場合は原因を修正し、実機へ反映できたことだけをもって完了とはしない。
