# issue #23: 中立判定の聞き返しを会話履歴へ残す

対象: [issue #23](https://github.com/kam6y/Cat-robot/issues/23)。main `7c03f693a6e3360bb03f32fa77ea07592c009451` から `codex/issue-23-neutral-history` を作成。

「今日の天気はどう？」→「今の、ぼくに言った？」→「言ったよ」の続きで元の話題を失わないよう、最初の利用者発話と固定の聞き返しを会話履歴へ保存する。既存の宛先判定・15秒の確認待ち・肯定/否定の振り分けは維持する。

## 方針と実装判断

既存の `ClaudeConversationService.recordExternalTurn(prompt:response:)` を `ConversationMemoryManaging` 経由で使う。新しい履歴ストアや一時的なプロンプト連結は追加しない。肯定表現の単語追加だけでは履歴保存を満たさないため、今回の修正には含めない。

`speakAndResume` に記録対象の元発話を明示的に渡す。正常なストリーム終了と `.finished` を確認した後、聞き取り再開より先に元発話と実際の固定返答を保存する。新しい会話・停止・削除などで所有世代が変わった完了は、再開を起こさない。正常に聞き返し終えた往復は、15秒の待機期限や後の否定で履歴から巻き戻さない。

既存の「うん」などによる肯定は元発話を再送するため、履歴は「元発話→聞き返し」「元発話→返答」の2往復になる。この経路は維持する。また、否定・期限切れ後も最初の往復は要約対象に残り、既存の要約モデルが未解決の質問として扱う可能性がある。今回、判定結果の種別や否定の記録は追加しない。

保存時点を読み上げ正常完了とするのは実装判断。既存の「失敗した聞き返しのpendingを破棄する」動作に合わせ、未完了の固定返答を履歴へ追加しない。既存の保存失敗時のメモリ内保持・未保存表示・再試行、セッション無効化、削除世代の防御を再利用する。聞き返し自体でLLM生成や利用回数加算はしない。

聞き取り再開までの待ち時間には既存ストアへの保存試行の時間も含まれる。次の応答へ渡る文脈はメモリ内の追加に依存し、ディスク保存の成功を待つ必要はないが、今回は既存APIによる保存試行を終えてから再開する順序を選ぶ。保存失敗は既存の未保存状態として扱い、成功を保証するものではない。固定返答を含めた履歴から次の応答を生成するため、キャッシュ済みClaudeセッションは無効化し、次回に作り直す。この保存待ちとセッション作成のコストは受け入れる。実時間やリモートのプロンプトキャッシュへの影響は未計測。

「言ったよ」は既存の肯定語一覧に無く、改めて宛先判定される。今回の修正は、その後に返答生成へ進んだ際の文脈を補うもので、分類器の判定結果や実モデルの意味解釈を保証しない。

## 確認する動作

- 実VM・実Claude記憶サービスで、元発話/聞き返しの1往復が保存され、次の「言ったよ」を扱う新セッションの文脈に入る。
- 保存を復元したサービスにも同じ文脈が届く。保存失敗でもメモリ内の文脈と未保存表示を維持する。
- 読み上げ途中・失敗・取消・`.finished`なしの終了では、未完了の固定返答を追加しない。
- 保存待ちと停止/削除が競合しても、聞き取りの復活や削除済み履歴の復活を起こさない。
- Smart Turn、エフォート4段階、推奨表示、返答生成・半二重・他者宛て/呼び名のみの扱いは維持する。

Swift/SwiftUIと既存依存関係を使い、モデル・資産・schema・追加依存は変更しない。Codexが単一writer、agmsgのClaudeがペア担当。実装後はClaudeの `/simplify` と独立コードレビューを並行し、双方が `receiving-code-review` で採否を検証する。関連テストと全体テスト後に、前回同様の統合を行う。
