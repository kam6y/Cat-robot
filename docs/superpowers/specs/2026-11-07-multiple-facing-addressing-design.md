# 複数人の顔向きによる宛先判定省略（issue #28）

## 目的と確定した要件

利用者が合意した[issue #28](https://github.com/kam6y/Cat-robot/issues/28)のとおり、顔が複数検出されても、有効でこちら向きの顔が1人以上あれば宛先分類を省略し、発話全文で返答生成へ進む。瞳の視線や発声者の同定は求めない。別の人の声に反応する可能性は、この人数条件の選択に含まれる。

## 採用する構成

既存の`ConversationCamera.hasFreshFacingFace(yawCorrection:)`の人数による拒否を外し、既存の`FaceTrackingGeometry.selectFace`で有効かつこちら向きの候補があるかを判断する。既存の選択処理は、顔向きで絞ってから中央付近等の優先順で選ぶため、中央の横向きの顔に隠されない。

選択肢として別の顔推定・話者対応付けや新しい判定器を作る必要はない。人数条件だけを緩和する現行処理の再利用が、今回の確定要件を満たす最小の変更である。

## 維持する契約

- 0.4秒未満の観測、現在のカメラ世代、許可・会話前面・聞き取り中・熱状態と不正値の検査を維持する。
- 左右補正とyaw左右30度／pitch上下25度の既存条件を使う。首の接続・追尾設定には依存しない。
- フィラー、15秒の確認待ちの肯定・否定優先、30秒／最大5分の会話継続を変えない。複数人の中で顔向きを確認できた場合も、従来の単独の顔と同様に継続窓を開始・更新する。
- 首の追尾対象選択やカメラ共有は変更しない。顔が利用できない場合は既存の経路に戻す。
- 発話の終了検出、モデル・effort・声、数値の読み、履歴保存は変更しない。#27と#29は別issueとする。

## 検証・ペア作業

既存のカメラ・会話・geometryを使ったテストで、複数人の1人だけ正面、全員正面、中央の横向きと別の正面、無効な顔と有効な顔の混在を検証する。全員横向き・角度不明・古い観測・権限や世代の失効なども維持する。実際の会話VMで分類器を呼ばず発話全文を返答へ渡すこと、live compositionでハード未接続・追尾OFFでも利用できることを確認する。

Codex Driver／Claude NavigatorでREDを作り、テストの区切りにClaude Driver／Codex Navigatorへ交代する。ソース編集は明示したDriverのみが行い、ビルド・試験中は双方が入力を固定する。次のGREENの区切り等で再び交代し、15〜30分を超えて同じ役割を続けない。agmsgの発言と差分で、レビュー・指摘・交代の実際を記録する。

最後にClaudeの実際の`/simplify`4観点と独立した1名のコードレビュー、相互receivingを行う。通常の実機版で複数人条件を確認し、全件検証・mainへの1コミットsquash・non-force push・issue完了確認まで前回と同じ手順で進める。
