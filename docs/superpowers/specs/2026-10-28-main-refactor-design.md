# Main全体のリファクタリングと旧資産整理

2026-10-28。基点 `69c2a22`（main / origin/main）。ユーザーはアプリ全体のリファクタリング、旧版の不要ファイル・文書・関数と不要ブランチの整理、agmsgでClaudeと協働することを依頼し、設計確認を挟まず実装まで任せると明示した。

## 目的と方針

現在の会話・音声・顔・カメラ・ハード操作を変えず、実際に動く経路を読みやすくする。旧比較実験の実装や、現役コードを検証しない旧テストを除き、現在の開発資料へ辿りやすくする。

小さいコメント整理だけでは依頼を満たさない。一方、全状態機械を新設計へ置き換える案は、所有権と非同期停止の再検証に対して効果が小さいため採らない。現役経路への集約と、明確な責務の抽出を段階的に行う。これはCodexの設計判断で、動作維持と無確認での実行はユーザー指定。

## コード

1. 本番未使用のAppleSpeechSynthesizerを専用テストとともに削除。短期のInMemoryConversationMemoryStoreはtest supportへ移す。現役のApple音声認識・音声セッション・端末内モデルによる代替・長期記憶のin-memory fallbackは残す。
2. 返答の再生を現役のSentenceReplyPlayback＋先読みへ集約する。ReplyPlaybackModeと古い全文/最初の一文/逐次比較経路を廃止し、依存型をSentenceSpeechSpeakingへ絞る。定型句用の単文speakとその内部の非先読み処理は維持。テスト用speakerはtest supportで文channelを扱い、統合テストを現役経路へ移す。LegacySupertonicSpeakerも廃止し、意味のあるPCM/失敗/停止の試験は現役speakerへ移す。実機runnerはvoices/fixed/lifecycleを保持し、fixedは現役モードだけ測定する。結果JSONのmodeはsentencePrefetchを維持する。
3. ConversationViewModelから、phaseに対応する表示設定、音声ターンの計測、共通の失敗処理を分ける。ViewStateにenter(_:caption:)、計測にはVoiceTurnLatencyRecorder、失敗方針はReplyFailurePolicyを用いる。captureのリセット、pauseの共通化は、現在の部分的リセットとcancel順の違いを明示したまま単純化できる範囲だけ扱う。サイズだけを目的にextensionへ分けない。
4. Motion/RobotLink/サービス層はClaudeの監査結果も確認し、根拠のある重複・不要状態を対象にする。安全条件や競合の判定順を変更してまで抽象化しない。

## 維持する契約

- iOS 27 / Swift 6、依存パッケージの固定版、顔80%、UI・VoiceOver文言、保存形式・保存先・互換ID・削除境界を維持。
- 生成途中の中断は保存せず、全文確定後の音声失敗では保存済み全文を残す。
- 音声開始後にハード予約を一度だけ解放する。古いターン/キャプチャのイベントを無視する。
- Taskのcancelと完了待ち、音声/認識/セッション停止の順序、世代照合を維持する。
- 文channelの背圧、最大1件の合成と1文先読み、本文2000文字の上限、安定prefixの検証を維持。
- 校正、リミット、停止、heartbeat、再接続、追尾/待機制御の安全条件を維持。実機操作は今回の整理には含めない。
- 本番と顔サイズツールで共有する描画、テストsupport、レンダーハーネスの参照画像を保つ。

## 文書

現在の構造を説明するarchitectureと文書索引を追加。完了済み計画、旧Gemma/MVPの仕様・検証、追跡済みのagent作業台帳、顔の途中比較画像を削除する。採用したneutral-b/happy-b/sleeping画像、出典、現役の詳細仕様・検証と未解決の実機事項は残す。削除した過去資料が必要なリンクは基点コミットのGit履歴へ向け、計測結果は書き換えない。

## Git整理

全参照のmanifestと検証済みgit bundleを恒久的なローカル保存先へ作る。古いブランチはsquashにより祖先判定だけで統合済みとは判定できないため、履歴を退避し、現在のmainへ新規に持ち込む必要がないことを分類してから削除する。remoteの削除は事前記録と先端が一致するものだけ。

未コミット変更のある6作業場所とそのブランチは保持。LocalAssetsのある古い作業場所も保全する。その他のclean worktreeはignoreされた作業台帳を保存してから通常のgit worktree removeで整理し、forceは使わない。mainと現在の作業ブランチは最後まで保護する。mainへの統合では通常のGit操作を用い、履歴を書き換えない。

## 分担・検証

CodexがGit、計画、再生経路・未使用実装の整理、文書、ビルドとテストを担当。Claudeはagmsgで監査・VM実装・差分レビューを担当し、変更ファイルは事前に固定する。ビルド中は双方のソースを凍結する。

基点は直前のmain統合で839件（837成功、実機専用2スキップ）、FW91件、Python9件、生成契約とServoDriverを検証済み。純粋な整理は既存の動作試験を再利用し、実装構造を写すだけの試験は増やさない。新しい責務の境界で不足する所有権・キャンセルの試験は先に追加し、欠陥を直す場合は再現試験の失敗を確認する。最後に全通常XCTest、顔サイズツール、Python、生成契約、顔レンダー、FWを実行する。全差分の独立レビューとClaudeの相互レビューを経てmainへ統合する。
