# Voice barge-in design — Issue #18

The cat must hear a person interrupt while generating or speaking, stop the old reply, and preserve the interruption's first words. Keep Claude, Supertonic, the selected voice, and the existing 1.2-second utterance boundary. The user delegated design choices to agreement between Codex and Claude on 2026-10-30.

## Approaches
1. Keep separate engines and reopen the raw microphone: small change but no reliable output reference for echo cancellation. Rejected.
2. Share an AVAudioEngine with Apple's voice processing between capture and PCM playback: retains the current models and voice, provides the output reference and independent capture/playback lifetimes. Selected by Codex and Claude after checking the installed SDK (iPhoneOS 27.1) and Apple voice-processing documentation.
3. Replace the model/audio stack with native realtime speech: changes voice and provider and exceeds #18. Deferred to #20.

## Audio and admission
A shared duplex engine owns the input tap, voice processing, player node, and graph. The audio session keeps the graph running across turn boundaries to avoid repeatedly resetting AEC. Capture stop releases its tap without stopping playback; playback stop discards all queued PCM without stopping capture. Audio-session deactivation stops the whole graph. Shared-engine playback is not other audio subject to the voice-processing ducking control. Voice-processing output dynamics may alter loudness or timbre and must be measured on device. An explicit async recognizer capability `supportsConcurrentPlayback` reports true only when the configured path is echo-cancelled; false retains existing half-duplex behavior. Failures must never silently enable raw listening over speaker output. Route changes and backgrounding stop both paths through existing lifecycle teardown. Paused typed-only replies use a playback-only audio session and an engine that has never created an input node; mode transitions rebuild the live engine after old leases are released. Typed requests replacing active listening retain the duplex session for voice resumption.

Before a voice reply starts generating or a fixed clarification starts speaking, open a fresh recognition stream with AEC. Keep it through the reply and promote it to ordinary listening on natural completion. Any nonempty lexical ASR partial/final is a candidate interruption; pure whitespace/punctuation is ignored. Preserve the same capture stream and segmenter across interruption. No audio is uploaded to a new provider and no transcript is added to logs.

## Turn cancellation
A capture may listen alongside exactly one reply turn. The first candidate synchronously invalidates that reply's ownership, cancels its task, closes the mouth, and releases motion. A single owned interruption task joins playback/generation and records delivery before a new reply may begin. ASR keeps filling the segmenter while teardown is pending; segmentation closing waits on that join. Late caption, playback, motion, or memory callbacks remain bound to their original turn. Stop/settings/background/route/reset supersede interruption and cannot restart listening. A failed duplex capture follows the existing recoverable audio failure path.

## Delivery and memory
Track the original text by sentence ordinal and separately track started/finished ordinals. An interruption snapshot retains only fully finished sentences and an explicit marker for interrupted playback; do not claim a partly spoken sentence was fully delivered. A task-local delivery UUID travels through primary, fallback and motion wrappers. The Claude service binds the latest delivery to its memory revision and operation epoch. After cancellation joins, replace only the exact latest committed turn (or append the interrupted turn when generation never committed), invalidate the cached model session, and persist. Never reset unrelated short- or long-term memory. Repeated/stale corrections, forget/reset, save failure, cancellation during compaction and the on-device fallback must be covered. Generic lifecycle cancellation retains existing memory semantics; this correction is specific to an accepted voice interruption.

## Validation and limits
Use deterministic fake recognizer/player streams for queued speech, delayed stop, multiple interruptions, stale callbacks, generation-before-playback, interrupted-before-first-audio, completed first sentence and partial second sentence. Verify audio ownership and failure unwinding independently with fake drivers. Run targeted tests then the whole simulator suite and an iPhone build. On-device validation uses known cat speech alone and known external speech, with detection-to-stop timing and first-word preservation recorded. Report acoustic limitations honestly; simulator tests cannot certify physical echo cancellation.
