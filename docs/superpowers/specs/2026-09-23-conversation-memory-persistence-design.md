# 会話の記憶の保存・復元

- 日付: 2026-09-23
- 状態: 2026-09-23、ユーザーの「ok」で承認済み。実装計画を作成し、実装前レビューへ進む。
- ブランチ: `feature/conversation-memory-persistence`
- 起点: main `392e763482c2bf8efe42deccf48f9c6bbe53f9fa`

## 1. 目的と合意した範囲

日常的に話しかける猫として、アプリを終了して開き直しても、前回の会話を踏まえて話せるようにする。ユーザーが了承した案は、正常な返答の完了ごとに「要約＋保持中の会話」を端末内に保存し、次回起動時に復元すること、および「会話を忘れる」操作を追加すること。

Gemma 4 E2Bを標準とし、12,288トークン上限、8,192トークン付近で要約、直近2,048トークン以上を往復単位で保持、要約出力上限512の方針は維持する。AFM実装は残す。

以下は設計上の提案とする。保存は既定で有効、保存先はアプリ内の単一ファイル、会話は一つ、端末間同期・バックアップへの記憶の収録は行わない。起動画面に端末内保存と削除方法を説明し、保存のための追加ダイアログは設けない。

成功とは「正常に保存できた直前の記憶を新しいサービスインスタンスで復元できる」「失敗や中断で未確定の会話を保存しない」「削除成功後に以前の記憶が復活しない」こと。要約の情報欠落やモデルの回答の誤りを、この機能で解決したとは扱わない。

## 2. 現在の実装

- `GemmaConversationService` actorが、要約文字列・確定した利用者/AIの往復・本文のトークン数をプロセス内に保持する。
- 要約後の候補記憶と新しい往復は、返答生成の成功とキャンセルの競合を解決した後、一緒に確定される。
- 一時停止・バックグラウンド移行は確定済み記憶を保持するが、プロセス終了・サービス再生成で失われる。
- 返答・要約・宛先判定は同じ推論エンジンを順番に使用する。ネイティブセッションを複数保持しない。
- `ReplyGenerating.reset()` は非throwingで、Gemmaではメモリを消す。現在の画面は主にAFMの `contextExceeded` 回復で呼ぶ。
- 字幕は生成途中から表示され、音声は全文生成後に読み上げる。保存対象となる完了は読み上げ完了ではなく、返答サービスでの生成・記憶確定である。

参照: `CatRobot/Conversation/Services/Gemma/GemmaConversationService.swift`、`GemmaRuntime.swift`、`CatRobot/Conversation/Integration/ConversationDependencies.swift`、`ConversationViewModel.swift`。

## 3. 保存方式の選択

| 方式 | 評価 |
| --- | --- |
| 現在の記憶を単一スナップショットとして保存 | 採用。現状の会話再構築に必要なデータだけを保存でき、永続化の単位と確定単位が一致する。 |
| 全文履歴をDBへ蓄積 | 今回は採用しない。履歴閲覧や検索には有用だが、現在の要件には不要。 |
| ネイティブ推論状態/KVキャッシュを保存 | 今回は採用しない。テキストからの再構築を維持し、ランタイム固有の状態に保存形式を依存させない。 |

保存先は `Library/Application Support/CatRobot/ConversationMemory/current.json` とする。モデルの配置先とは別ディレクトリにする。保存用一時ファイルは同じディレクトリ内に作り、完全なファイルを書いてから既存ファイルを原子的に置き換える。旧版と新版を混ぜない。旧記憶の世代バックアップは作らない。

ロック中は読み書きできないファイル保護を適用し、記憶ディレクトリ・確定ファイルをOSバックアップ対象から除外する。ディレクトリと一時ファイルの必要な属性を置き換え前に設定し、失敗したら旧ファイルを残す。置き換え後も属性が保たれる実装を選び、実機で検証する。原子的置換の成功を保存の確定点とし、以後の診断失敗を「旧版のままの保存失敗」と報告しない。独自暗号方式・Keychainへの本文保存は追加しない。ロック等によるアクセス拒否を「保存ファイルなし」と解釈しない。

## 4. 保存データ

スナップショットの形式は次のとおり。

- `schemaVersion`: 初版は1。
- `memoryCompatibilityID`: モデル・tokenizer・履歴の解釈の互換性を識別する、アプリ管理の固定値。アプリのビルド番号ではない。
- `revision`: 同じ会話の保存世代。新しい確定記憶ごとに増やす。
- `savedAt`: 保存時刻。鮮度表示や調査に使い、書き込み順序の判定には使わない。
- `summary`: 現在の要約。要約前なら空文字列。
- `turns`: 確定済みの往復の順序付き配列。各要素は `prompt` と `response`。

本文のトークン数は保存データを信用せず、復元時に現在のtokenizerで再計算する。システム指示は現在のアプリから供給する。KV、生成途中の文、要約中の候補、音声、宛先判定、無視した発話、保留中の聞き返し、UI状態、エンゲージメント期限は保存しない。

過去に要約で捨てた全文は復元できない。保持中の本文は常に2Kではなく、次の要約まで増える。8K到達後に確定したスナップショットも正常であり、復元時に8K超過を理由に捨てない。

読み込みはデコード前に1MiBのファイルサイズ上限を確認し、必須フィールド・バージョン・互換性ID・空でない往復を検証する。初版の上限は意図的に現在の12K会話より十分大きくする。1MiB以内でも推論予算を満たす保証にはならず、tokenizerと既存の送信前チェックを必ず使う。書き込み側にも同じ形式・サイズ制約を適用する。

## 5. 責務と境界

### 保存ストア

`ConversationMemoryStore` の抽象とファイル実装を追加する。`load`、`save(snapshot)`、`clear` をthrowingな操作として提供する。ファイル実装はactorなどの単一の直列経路でアクセスを処理し、UIや推論から直接ファイルを操作しない。

テストでは一時ディレクトリを使う実ストアと、読み書き失敗・遅延を再現するfakeを注入できるようにする。既存のGemma単体テストは明示的なインメモリストアを利用し、利用者の実ファイルへ触れない。通常アプリの `ConversationDependencies.live()` がファイルストアを注入する。

### 会話サービス

Gemmaサービスが、ロード状態、確定記憶、保存世代、未保存状態、進行中の処理を管理する。永続化対象を生成するのはこのサービスだけとする。ストアはどの会話を保存すべきか判断しない。

記憶操作用に `ConversationMemoryManaging` 境界を追加し、明示的な準備、状態通知、保存再試行、忘却を提供する。具体的なSwiftシグネチャは実装計画で定義するが、少なくとも `prepareMemory`、`retryMemoryOperation`、throwingな `forgetConversation`、状態の観測が可能であること。`prewarm()` の既存の非throwing契約へ復元エラーを隠さない。

AFM用には永続化非対応の実装を用意し、既存の返答・リセット動作を維持する。AFMへGemmaの保存データを渡さない。UIはモデル固有のファイル名やエラー型を扱わない。

## 6. 保存のタイミングと整合性

1. 現在と同じように生成・必要な要約を行い、候補記憶を作る。
2. キャンセルとの競合を解決する。失敗またはキャンセルが勝った場合、候補は保存しない。
3. 成功した場合は確定記憶を更新し、世代付きの不変スナップショットを作る。
4. 同じターン処理の中で保存をawaitする。保存完了または保存失敗の状態通知まで次のターンを開始しない。生成した字幕は従来どおり逐次表示できる。
5. 保存に成功すれば保存済み状態にする。保存に失敗しても、成功した返答とRAM上の記憶は保ち、返答ストリームを生成失敗にはしない。画面に未保存状態を通知してから正常終了する。

保存確定前にプロセスが終了した場合は最後に保存できた世代へ戻る。画面に表示済みでも、生成中・保存中の最新往復は失われ得る。通常の生成成功・保存成功の後は、読み上げ中に停止してもその往復は残る。

保存失敗時、ディスク上の旧スナップショットを保持する。次の正常な返答時には最新のRAM上の記憶全体で再試行する。ユーザーが「保存を再試行」を押した場合も、失敗した古い世代ではなく現在の確定記憶を保存する。各ターン内で保存の結果まで待つ設計とし、終了通知だけに保存を依存させない。

## 7. 復元

会話準備時に保存データを読み込み、モデル準備後にtokenizerで再計数する。ファイル読み込み・再計数は一つの準備タスクへ合流させる。文字入力からの初回返答でも準備を通し、UI経路によって復元を飛ばさない。

- ファイルがない場合: 新しい空の記憶で開始する。
- 対応形式の正常なファイル: 検証済み記憶を一度だけ採用する。その後はRAM上の確定記憶を正とし、一時停止・再開でディスクを再ロードしない。
- 壊れたJSON、未対応schema、互換性不一致、上限超過: ファイルを勝手に削除・上書きせず、会話開始を止めて復元失敗を表示する。
- ロックや一時的なI/O失敗: データを残して「再試行」を提供する。

復元失敗時は「保存した会話を読み込めませんでした。再試行するか、記憶を消して新しく始められます」と案内する。ユーザーが忘却を明示的に選ぶまで、新しい会話で旧ファイルを上書きしない。初版では旧形式の移行や別モデルへの自動変換は実装しない。

復元自体では要約を生成せず、返答セッションをテキストから再構築する。次の返答時には従来どおり、必要なら要約し、初回の履歴再読み込みを含め12K予算を検査する。復元に伴ってマイクや読み上げを勝手に開始しない。起動時の「会話を始める」操作とバックグラウンド復帰時の明示再開は維持する。

## 8. 会話を忘れる

会話画面の補助メニューに「会話を忘れる」を追加する。確認文は「このiPhoneに保存した会話の記憶を削除します。元には戻せません。」、選択肢は「削除する」「キャンセル」。復元失敗時にも同じ忘却操作へ進める。

削除確定後は次の順序で処理する。

1. 画面側で新規入力と再開を止め、マイク・読み上げ・進行中のターンを停止する。
2. サービス側でも忘却中フラグを先に立て、新しい推論・ロード・保存を受け付けない。
3. 生成のキャンセル終端、進行中の復元・保存を待ち、旧操作が以後の書き込みを予約できない状態にする。
4. ストアの直列経路で確定ファイルと未確定の一時ファイルを削除する。ファイル不在は成功として扱う。
5. 削除成功後、ネイティブ返答セッションとRAMの要約・往復を消し、保存世代を新しい会話として初期化する。画面の字幕・認識文・入力欄・保留中の聞き返し・エンゲージメントも消す。
6. 「会話の記憶を削除しました」と表示し、一時停止状態にする。次の会話は明示操作で開始する。

actorはawait中に再入可能なので、actor化だけでこの順序が守られるとは考えない。処理のゲートと世代確認を組み合わせ、削除をまたいだロード結果の採用や古い保存を禁止する。非同期操作の失効には、保存ファイルのrevisionとは別のプロセス内の世代を用いる。この世代は忘却時に進め、新しい会話でゼロへ戻さない。保存タスクをfire-and-forgetにしない。

削除に失敗したら完了表示は出さず、停止状態を維持して再試行を提供する。旧記憶がディスクに残る可能性を明示し、削除成功まで新しい会話を開始しない。アプリ終了後に削除の再試行が必要になる可能性はあるが、成功していない削除を保証済みとは扱わない。

Gemmaの既存 `reset()` も同じ忘却処理へ集約し、RAMだけ消して再起動時に古い記憶が戻る経路を作らない。非throwing契約のため、失敗は記憶状態の通知に載せ、そのサービスで新しい返答を開始させない。新しいUIの明示的な削除はthrowingな `forgetConversation` を使い、完了を確認する。AFMの `reset()` は変更しない。

## 9. 画面と利用者への説明

- 起動画面に「会話の記憶はこのiPhoneに保存され、いつでも削除できます」を追加する。
- 保存成功のたびにトーストや音声は出さない。通常の会話を遮らない。
- 保存失敗時は「会話を保存できませんでした。アプリを閉じると、最新の会話を忘れることがあります」と「保存を再試行」を表示する。生成のエラー表示とは分ける。
- 復元・削除の失敗は会話開始を止める回復状態、保存失敗は会話を続けられる通知として区別する。
- 読み込み・保存・削除の内部詳細やJSONを利用者へ表示しない。VoiceOverには状態変化を一度だけ伝える。
- 会話本文や要約をログへ出さない。必要な計測は所要時間・成功/失敗・世代・エラー分類だけとする。

## 10. 変更予定の範囲

- Gemmaサービスと記憶型: 保存スナップショットの生成、ロード、準備/忘却の排他、保存状態の通知。
- 新しい保存ストアとデータ型: ファイルI/O、形式検証、原子的置換、削除。
- `ConversationServices.swift` / `ConversationDependencies.swift`: 記憶管理境界と注入。
- `ConversationViewModel.swift` / `ConversationAppCoordinator.swift`: 準備・通知・再試行・忘却・ライフサイクルの連携。
- 会話画面・状態・アクション・起動画面: 補助メニュー、削除確認、保存に関する説明と回復表示。
- 対応テスト、README、検証記録。Swiftファイル追加時は既存の生成スクリプトでXcodeプロジェクトを更新する。

既存の巨大なViewModelを全面的に作り直すことは含めない。記憶保存のために必要な状態と操作の追加に限定する。

## 11. 検証と受け入れ条件

### 自動テスト

- 要約なし・要約ありの往復を保存し、新しいストア/サービスで同じテキスト・順序を復元できる。
- 復元した記憶が返答セッションに渡され、8K到達済みの記憶も既存の要約と12K予算チェックを経て扱われる。
- 初回の並行準備が一つのロードへ合流する。一時停止/再開は再ロードしない。文字入力でも復元を飛ばさない。
- 要約または返答の失敗・中断、宛先判定、無視した発話が保存内容を更新しない。
- 生成成功とキャンセルの競合が保存の確定にも一貫して反映される。
- 保存失敗で返答・RAM上の記憶を失わず、旧ファイルが有効なまま残り、再試行で最新世代へ更新される。
- 復元失敗・未対応schema・モデル互換性不一致・過大ファイル・アクセス拒否で、空の会話による上書きを行わない。
- 保存途中の失敗後に読み込めるのは完全な旧版または新版であり、途中のJSONではない。一時ファイルを正式な記憶として読まない。
- ロード中・保存中・推論中・再試行中の忘却で古い記憶が復活しない。遅延fakeを使って処理順を固定し、sleep頼みの競合テストにしない。
- 削除成功後の新しいサービスは空で始まる。削除失敗時は成功表示を出さず、再試行まで会話開始を止める。
- 字幕・入力欄の消去、VoiceOver通知、保存失敗中の会話継続、復元失敗中の開始禁止をUI状態のテストで検証する。
- AFMの既存リセット・通常会話、マイクの明示再開、Gemmaのキャンセル終端処理を維持する。

### iPhone 16 Pro

合成の会話だけを使い、実機確認のために普段の保存記憶を消さない。自動実機テストは専用の保存ディレクトリを注入して隔離する。

1. 好みとその訂正を会話し、保存成功を確認してプロセスを終了する。再起動後の回答を記録し、保存データの復元成否とモデルの想起の成否を分けて評価する。
2. 自動要約を一度以上経た記憶でも終了・再起動・続きの会話を確認する。
3. 一時停止・バックグラウンド・ロック・再開で保存エラーの扱いを確認し、勝手にマイクが再開しないことを確認する。
4. 「会話を忘れる」を実行し、再起動後も以前の記憶がモデル入力へ渡らないことを確認する。
5. 実ファイルの保護/バックアップ除外属性、残存一時ファイル、保存/復元の所要時間を確認する。会話本文は診断ログへ出さない。

Simulatorの全通常テストとプロジェクト生成の決定性チェックを通す。実機テストの成功だけを記憶内容の完全性の証明にはしない。

## 12. 今回含めないもの

全文の会話履歴画面、複数会話、ユーザープロフィールや事実の別DB、記憶検索、クラウド同期、エクスポート、モデルダウンロード、要約ポリシーの変更、先回り要約、文単位読み上げ、推論ランタイムの変更は別機能とする。

本書のレビュー後、実装計画を作成する。今回はfeatureブランチと本specのみを作成し、実装には着手しない。
