# Idle sleeping design

The user requested a new `sleeping` expression, `sleepy` after five minutes without being addressed, and sleeping standby after ten total minutes. Both thresholds are configurable. The user confirmed that standby stops microphone, camera and automatic neck motion, keeps the sleeping face visible, and resumes only when the face is tapped. Implementation is paired with Claude. The user additionally requires an image_gen draft, Claude-authored vector reconstruction, and comparison against the draft.

## Approach
Use one inactivity owner alongside the existing app coordinator. The conversation view model reports accepted addressed speech and typed turns; the inactivity owner uses the existing injectable RobotClock protocol with a ContinuousClock-backed production clock that includes device sleep. This reuses the coordinator's existing microphone, camera, motion and lifecycle cancellation paths. A view-only timer cannot reliably control these resources; putting all hardware state in the conversation engine would duplicate app lifecycle ownership.

## Behavior and implementation decisions
- Defaults are 5 and 10 minutes measured from the latest accepted addressed speech, accepted typed submission, or explicit face tap/start. Background speech, failed recognition, model replies, camera events, and settings navigation do not count as addressing the cat.
- Wake-only calls and classifier-confirmed addressed speech reset the timer. Ambiguous/not-addressed speech does not.
- Speech already being recognized at the deadline finishes segmentation before sleeping; provisional-only recognition is released by the existing 20-second utterance maximum. This bounds segmentation, not the recognizer’s graceful finalization; finalization keeps the existing owned completion wait without a separate timeout. This defers sleep without resetting its deadline. Typed drafts are preserved while their panel is hidden during standby.
- A reply, classification, preflight, or clarification in progress finishes before inactivity can pause the conversation. The elapsed time is preserved; re-evaluate when listening resumes.
- Thresholds are whole minutes, persisted in UserDefaults, with 1–1439 minutes for sleepy and 2–1440 minutes for standby; standby must be later than sleepy. Editing a threshold keeps the pair valid and the UI explains that both run from the last interaction. Both steppers are in Settings → 会話 → 居眠り under the 2026-10-27 UI reorganization.
- Settings/background pause scheduling but preserve elapsed time. On return, evaluate before any automatic microphone restart. Once asleep, foreground/settings/new-conversation/conversation-recovery cannot wake it. Memory saving can be retried while remaining asleep. Only the face tap explicitly clears sleeping.
- Standby holds the display wake lock while the conversation is visible so the sleeping face remains visible. It disables conversation camera/tracking/look/expression tools and puts automatic motion into inactive mode. Settings can still be opened for inspection and manual adjustments, without waking the conversation.
- Sleeping presentation wins over a held expression or look state, clears old captions, and shows a “待機中・タップで起こす” status chip. It suppresses pause/look chips while preserving reconnect and heat warnings; the sleeping face remains fully opaque. Sleepy is shown while idle/listening/paused, including manual pause and typed-only idle. Terminal errors keep their error face until standby but still count toward inactivity.
- Add a closed gold eyelid shape with the current coral nose and cream mouth/whiskers. Existing nine expressions and their geometry remain unchanged. Sleeping is an application state, not an LLM express-tool choice.
