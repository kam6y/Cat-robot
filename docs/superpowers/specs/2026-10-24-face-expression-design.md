# 猫の顔の再デザインと express の設計

日付: 2026-10-24。見た目の採用案を2026-10-26に更新。基点: `feature/claude-neck` / `b628ddd`。
状態: 通常顔は画像生成のB案、happyは目を大きくしてきらめかせた修正版を利用者が採用。2026-10-26に実装開始と、Claudeのsubagentによる反復比較・修正を承認。Claudeとのagmsg相談を反映する。

## 目的と確定している範囲

黒いロボットの外装に画面をなじませ、聞いている・考えている・話している状態と、返答の感情を顔で伝える。当初要件の FR-FACE-1〜5・7〜8 と、`express` に関する FR-CONV-9 を今回の対象とする。

利用者の実機写真を参考に3案を画像生成し、丸い琥珀色の目を持つB案を採用した。happyは「目を大きくして光らせる」という指定を反映した修正版を採用した。黒背景・画面内に耳を描かない・明るい目・小さな鼻口・細いひげを維持する。以下の寸法、表情の優先順位とタイミングは、採用画像と当初要件を実装するための設計上の判断である。

対象は SwiftUI の顔の描画、9表情、会話状態との連動、`express` ツール、音声イベントに連動する口、顔を中心にした会話画面への配置変更。文字入力・設定・一時停止・エラー復旧・記憶の保存通知は引き続き利用できる。字幕の画面表示は後続の画面整理設計で廃止し、返答の全文はVoiceOverと記憶に保持する。

瞳を実カメラの顔方向へ動かす FR-FACE-6 は推奨要件として別実装へ残す。現在の顔追尾はロボット接続と姿勢の取得を稼働条件に持つため、今回の表情表示へその条件を持ち込まない。`look`、おやすみ機能、自動時刻設定、権限オンボーディングの再編も今回には含めない。`sleepy` は表情だけで、マイクや首を停止する指示ではない。

## 現状と採用方式

現在の `CatFaceView` / `CatFaceShapes` は参照イラストをトレースした頭の輪郭・耳・模様を持つ。`ConversationView` は猫と字幕の左右配置で、`CatVisualState` による表示と `MouthPose` による口の状態がある。首のツールは `MotionTurnContext` で呼び出し元ターンを識別し、`ReplyPlaybackCoordinator` が実際の発話開始を一度だけ通知する。

採用: **SwiftUI のベクター描画を置換し、小さな表情コーディネーターを追加する**。会話・音声・首の既存境界を利用する。描画は値型の表情と口の状態を受け取り、BLEやモデルへアクセスしない。

検討した別案:

- 現行イラストへ9種類の差分を足す: 変更量は小さいが、耳なし・外装と一体の全画面顔という要件と合わない。
- 画像アトラス、3D、外部アニメーションエンジン: 制作資産と依存が増え、目・まぶた・口・ひげの個別変形やアクセシビリティ対応にも別の仕組みが要る。今回の2Dの顔には不要。

Swift 6 / iOS 27以上 / 横向き両方向を維持し、追加パッケージ、新しいカメラ処理は導入しない。生成画像は設計資料として保存し、アプリの表示はSwiftUIのベクター描画で再現する。

## 見た目

採用した基準画像:

- [通常顔・B案](../../design/face-expression-2026-10-26/neutral-b.png): 丸く大きな琥珀色の目、太い縦長の黒い瞳、小さなコーラル色の鼻、クリーム色の口とひげ。
- [happy・採用した修正版](../../design/face-expression-2026-10-26/happy-b.png): 両目を開いたまま約18%拡大し、瞳も少し大きくする。明るい金色、瞳の中の四つ星形と丸いハイライト、目の縁の控えめな光で喜びを表す。静止時の口は小さく閉じた笑顔。
- 内蔵`image_gen`で生成した。[通常顔のプロンプト](../../design/face-expression-2026-10-26/neutral-b.prompt.txt)と[happyのプロンプト](../../design/face-expression-2026-10-26/happy-b.prompt.txt)を保存する。

画像は顔と外装の見え方を合わせる基準で、字幕・状態表示・操作を省いた製品画面仕様ではない。配置には後述の会話画面とアクセシビリティの要件を適用する。通常顔をアーモンド形に戻したり、happyを目を細めた笑い目へ置き換えたりしない。残り7表情もBの丸い目と配色から派生させる。

通常の会話では純黒 `#000000` を画面端まで敷き、目・鼻・口・ひげだけを描く。頭の輪郭、耳、額の模様、明るい口周りの面は描かない。採用画像へ合わせる初期配色は、目が琥珀色 `#FFC94F` と陰影 `#D9951B`、ハイライトが `#FFF8E9`、鼻がコーラル色 `#FF967A`、口とひげがクリーム色 `#FFF0CC`。これは画像の画素値の測定結果ではなく描画調整の出発点で、基準画像との比較で整える。色だけで表情を区別しない。

顔専用の16:9正規化キャンバスを、後述の会話画面の顔領域へ等比配置する。目の中心は `(0.32, 0.40)` と `(0.68, 0.40)`、基本の目の大きさは幅0.22・高さ0.39を出発点とし、実寸で丸く見せる。鼻の中心は `(0.50, 0.64)`、口の中心は `(0.50, 0.73)`。ひげは左右3本ずつ。詳細な曲線の制御点・間隔・大きさは採用画像と実際の会話画面を比較して調整し、顔を主体に見せる。happyの拡大と光を含め全プリセットが枠から出ず、目・鼻・口・ひげが重ならないことを確認する。

| プリセット | 目・まぶた・瞳 | 口・ひげ |
|---|---|---|
| neutral | B案の丸い目、太い縦長の瞳は中央、小さな丸いハイライト | 小さく閉じた猫の笑顔、自然なひげ |
| happy | 丸い目を開いたまま約18%拡大、瞳も少し拡大、明るい金色と四つ星形のハイライト、控えめな縁の光 | 小さく閉じた笑顔を保ち、ひげをわずかに上げる |
| curious | 片側を少し大きく、瞳を少し上へ | 小さい口、片側のひげを少し上げる |
| thinking | まぶたを少し下げ、瞳を片側上へ | 口は控えめ、ひげは水平寄り |
| listening | 両目を少し大きく、瞳を中央へ | 閉じた口、ひげを少し前向きに見せる |
| speaking | neutralを基に少し開いた目 | 再生イベントによる口の開閉を重ねる |
| sleepy | 上まぶたを下げた細い目 | 小さい口、下がったひげ |
| surprised | 丸く大きい目、小さめの瞳 | 小さい丸い口、少し広がったひげ |
| sorry | 目の内側を少し上げ、まぶたを下げる | 控えめな口、下がったひげ |

顔のパラメーター変更は通常0.25秒で補間する。待機時のneutralだけ、3.5秒ごとに0.10秒で閉じ、0.12秒で開くまばたきを行う。画面外・非active・一時停止中は周期アニメーションを動かさない。Reduce Motionでは補間と自動まばたきを止め、表情の静止形と発話中/終了の口の違いは残す。happyのハイライトと縁の光は静的な描画として残し、点滅や周期的な明滅は追加しない。

## 状態連動と表示の重ね方

| 会話の状態 | 自動表情 |
|---|---|
| idle / paused | neutral（pausedではまばたき停止） |
| preparing / classifying / thinking | thinking |
| listening | listening |
| clarifying | curious |
| speaking | speaking |
| failed | sorry |

自動表情の唯一の入力は `ConversationViewState.phase` とし、`FaceExpression.automatic(for:)` のこの表から決める。描画の置換後に参照がなくなる旧 `CatVisualState` / `catState` と代入を削除し、自動表情の状態を二重に持たない。期限内の `express` があれば表情だけを一時的に上書きし、期限後は**その時点**の自動表情へ戻る。以前の会話状態を復元しない。

発話の口は独立レイヤーで、happyやsorryを保持していても実際の再生に合わせて動く。`express("speaking")` だけで音声や口の周期動作を開始しない。口の開閉が終わったら、その表情の静止した口へ戻す。首の接続やカメラ許可がなくても表情は使える。

## express の契約

- 引数は `expression`（9種類の文字列）、`hold_seconds`（省略は3、1〜10秒）。大文字小文字と前後の空白を正規化し、未知の表情はneutral、秒数は1〜10へ丸める。これは当初要件の「不正値はツール側で既定値に丸める」に合わせる。
- ツールは表示完了を待たず、日本語の短い予約結果を返す。スキーマ上の名前は必ず `hold_seconds` とし、Swift側の都合でcamelCaseに変えない。
- 既存の `MotionTurnContext.current` / `MotionTurnID` を呼び出し時に捕捉し、MainActorへの移動後も同じIDを使う。現在のターンを後から推測しない。今回は名前の一般化や全体のイベントバスは作らない。
- 発話前は最新の1件だけ予約する。同じターン内の次の呼び出しで置き換える。最初の実再生開始通知で表示し、その時点から保持時間を測る。生成や合成待ちの時間は保持時間に含めない。
- 同じターンの発話中に新しい呼び出しが来たら直ちに置き換え、置換時点から保持時間を測り直す。履歴キューは持たない。生成完了後、発話終了後、取り消されたターンからの追加予約は受け付けない。
- 生成が成功して発話開始を待っている予約は保持する。発話が先に終わっても、既に表示中の表情は期限まで残せる。ただし新しい会話ターンが始まったら前の表情を消す。
- 明示停止、新しい会話、生成/再生失敗、fallbackへの切り替え、設定を開く、inactive/background、会話画面を離れると予約・表示・期限タイマーを取り消す。復帰時は自動表情だけを表示する。
- `.idle` / `.preparing` / `.paused` / `.failed` へ移った場合も現在のターンを無効化する。`listening` / `thinking` / `classifying` / `clarifying` / `speaking` の間の遷移だけでは、期限内の表示を消さない。新しいターン開始はそれらの遷移とは独立して前の表示を取り消す。
- 遅延した旧ターンのツール、旧タイマー、旧再生完了は新しいターンの表示を変更できない。表情タイマーは表示中の1件だけで、常駐ポーリングはしない。
- ターン外や取り消し済みの呼び出しは「この返答の表情は変更できません」と返し、表示を変えない。非表示時は「今は表情を変えられません」。正規化した予約は「うれしい表情を3秒予約しました」のように実際に採用した値を返す。

端末内モデルには現在ツールを渡していない。今回その生成経路を拡張しないが、fallbackに入った時点でClaude由来の表情予約を取り消し、通常のlistening/thinking/speaking表示と口の動きは継続する。推奨要件FR-LLM-5の端末内ツール対応は別課題として記録する。

## 音声との接続

首の開始通知は既存どおり返答につき一度だけ。表情の初回予約もこの通知に同期させる。アプリが扱う再生開始イベントでの同期であり、音声サンプルとディスプレイ走査の厳密な同時性は保証しない。

`SentenceReplyPlayback` は現在、文ごとのstarted/finishedをtraceに記録しつつ、UIへは最初と最後しか転送していない。文単位の口の開閉用に `sentenceStarted(ordinal:)` / `sentenceFinished(ordinal:)` を追加し、文開始で既存の口の大きさの列（wide→medium→small）を1段進め、文終了で閉じる。Supertonicは元文字列の単語時刻を提供しないため、PCM位置を単語位置として扱わず、音素解析も追加しない。一文の再生中に周期タイマーで口を開閉する機能は今回追加しない。

従来の `SpeechSpeaking` 経路では既存のstarted / willSpeak / finishedによる `MouthPose` を維持する。追加の区間通知で会話phaseをlisteningへ戻したり、次の文で首を再度開始したりしない。キャンセル・合成失敗・音声経路切替時は口を閉じ、遅れた通知を捨てる。

文終了でclosedの状態へ更新することを検証する。先読みした次の文が直ちに始まる場合、閉じた形が一定時間見えることまでは保証しない。今回、最低閉口時間を作るために音声や次の文の表示を遅らせる仕組みは加えない。

## 会話画面とアクセシビリティ

2026-10-27の[画面整理設計](2026-10-27-ui-reorganization-design.md)に従い、通常表示は全画面幅・高さの85%の枠に顔を等比配置する。顔の横位置はsafe area内の中央、縦位置は全画面の中央とし、右上に44pt以上のメニュー操作領域を残す。顔タップで聞き取りを一時停止・再開する。

字幕・聞き取り途中の文字・通常の活動状態は画面には出さない。返答の完全な文字列は `ConversationViewState.caption` と会話の記憶に保持し、既存の `ConversationAnnouncementPolicy` がVoiceOverへ全文を渡す。左上にはタップで再開する一時停止、撮影中、自動待機、接続済みの首の再接続、熱による追尾停止の状態チップを表示する。一時停止チップの間だけ顔を不透明度0.5にし、待機中は寝顔を暗くしない。記憶のお知らせは下部中央のカプセルに出す。

最大Dynamic Type、文字入力・キーボード表示、エラーや記憶復旧カードがある場合は操作の読みやすさを優先し、顔を縮小してスクロール可能な配置にする。マイク状態は顔ボタンの既存のアクセシビリティ値で伝え、エラー復旧・記憶通知のラベルと設定導線を維持する。システムのステータスバーは現状どおりとし、表情変化やまばたきのたびにVoiceOverへ割り込まない。装飾パーツは個別の読み上げ対象にしない。

## 構成と検証の境界

- `FaceExpression`: 9種類、引数の正規化、自動表情への対応表。
- `FaceExpressionCoordinator`: ターンごとの予約、表示、取消、期限。`RobotClock`を再利用するがRobotLinkには依存しない。
- `ExpressTool`: Foundation Modelsのツール境界だけ。
- 顔の姿勢/形の値と `CatFaceView` / `CatFaceShapes`: ベクター描画、口との合成、動きの抑制。
- `ReplyTurnObserving` / `ReplyTurnMulticaster`: 既存の5通知（beginTurn / speechStarted / speechFinished / generationFinished / cancelTurn）だけを抽出し、首と表情へ順に渡す。新たな状態、タスク、時計は持たない。`RobotMotionControlling` はこのプロトコルを継承する。
- `ReplyPlaybackCoordinator` / `MotionReplyGenerator` / `OnDeviceFallbackReplyGenerator`: 既存の通知先の型を共通プロトコルへ変更し、compositionが作る同じmulticasterを使う。既存の引数ラベル`motion:`は互換性のため保持する。MotionCoordinator本体や追尾・BLEの配線は変更しない。表情の通知は非throwingで、音声を止めたり合成を待たせたりしない。
- `ConversationViewModel`: 既存のmotionへのphase通知と同じ同期位置で表情へもphaseを通知する。停止・新しい会話・shutdownの入口でも表情をresetし、SwiftUIのonChangeだけに取消を任せない。
- `ConversationAppCoordinator`: カメラの可視条件を更新する既存の地点で、表情にも会話画面かつactiveかつ設定を開いていないことを同期通知する。顔追尾が注入されていない場合にもこの通知を省略しない。
- `AppRootView`: ロボット状態と同様に、読み取り専用の`heldExpression`を`ConversationViewState`へ合成する。SwiftUIが観測する本体はcompositionの同じ表情コーディネーター1つ。

共通のターン通知先と、phase/画面可視性を受け取る表情の通知先を `ConversationDependencies` に保持する。既存テスト向けの既定値はno-opとし、共通ターン通知先を省略した場合は既存のmotionを使う。`RobotConversationToolProvider` も同じ表情インスタンスを使用する。BLE切断の処理は引き続きMotionCoordinator内だけで行い、表情の取消へ変換しない。

ホスト試験は正規化、保持の時刻境界、順不同/旧世代の通知、fallbackと画面遷移、全9表情と口の合成、首の開始回数を検証する。静止画は既存のRobotPresentationTestsと同様、UIHostingControllerとUIGraphicsImageRendererで自動生成しXCTest添付画像に残す。表情・固定サイズ・isAnimating=falseを明示して9表情を決定的に描き、画像の合否は目視する。両横向きのsafe area、通常/最大文字、Reduce Motion等は代表的な表情を使った画面fixtureで確認し、不要な全条件の直積は作らない。SwiftUI previewは任意の調整用とし、自動生成する確認画像の代わりにしない。実機では既存の首・追尾・会話を併用した時の見た目と反応を確認し、未実施のものは未実施として残す。

設計の受入条件は、黒い外装に顔がなじむこと、表情を目の形から読み取れること、表情の期限や取り消しで前の会話が復活しないこと、文終了イベントで閉じる状態へ戻ること、既存の会話操作が失われないこと。まず実装中の9表情一覧と通常会話画面で見た目を確認し、微調整は同じベクター構成の範囲で行う。

## Claudeとの設計確認

agmsgで再召喚したClaudeと既存コードを照合し、共通ターン通知・文ごとの口イベント・表情の独立した期限管理を採用した。builder checkの3点は、(1) 最小閉口時間を設けずイベントの状態遷移を契約にする、(2) 決定的なXCTest添付画像を自動生成し目視確認する、(3) 自動表情をphaseから導出して旧catStateを削除する、で解消した。未確定の利用者判断を実装者へ渡さない。最終的な曲線の微調整は描画Taskの範囲とする。
