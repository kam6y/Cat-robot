## 1. 目的と完了条件

iPhone の既存の会話アプリから、組み立て済みの Cat Robot の首を BLE で動かす。初回の接続先選択、以後の再接続、中立と方向の校正、Claude の `move_head`、発話開始との同期を一つのサブシステムとして作る。首が使えない間も会話は続ける。

完了時に利用者ができること:

1. 設定から近くの `CatRobot-XXXX` を選び、接続と状態を確認する。
2. 横向きの校正画面でオフセットと反転を試し、ロボットに保存する。電源再投入後も値が残る。
3. 会話の返答に合わせて頷き・横振り・かしげ・見上げ・うつむき・正面への移動が出る。
4. 接続が切れたら首の要求は破棄され、会話が続く。再接続後に古い動作を再生しない。
5. 既存の音声認識、文単位先読み、記憶・モデル選択・設定操作が引き続き動く。

顔の描き直し、カメラ、実際の顔追尾、`express` / `look`、おやすみの画面と音声コマンドはサブ計画 4。ここでは追尾・おやすみを受け入れる境界を用意する。ファームウェアの改造、ゲイン校正の GUI 化、OTA、バックグラウンド BLE、クラウド中継は含めない。

失敗とみなすこと: 会話の開始を BLE の接続待ちにする、生成中に首を動かして発話とずれる、再接続で予約を再生する、校正中に自動動作が割り込む、GATT の書き込みだけで保存成功を表示する。

## 2. 決定と方式の比較

### 利用者の決定

- ファームウェアは実機で選んだ波形出力方式を使う。滑らかさのために動作時間が延びることを受け入れる。
- 1 ターンの動作は **4 秒を目安に追加予約を抑える。開始した 1 サイクルは最後まで行う**。約 4.1 秒の見上げ・うつむきも 1 回は実行できる（2026-10-23 の回答）。
- 接続と校正は、ブラウザで確認した画面案 01 の構成で進める。既存の横向き・ダーク表示を保つ。校正画面にオフセット、反転、方向別の動作確認、停止、保存をまとめる。
- 連続する MOVE の送信中は `speed` を固定し、変える場合は静止してから再開する（FR-MOV-13、合意済み）。
- PWM 停止後も DS3218 が最後の位置を保持することを受け入れる。「停止」を、手で首を動かせる状態と案内しない。

### Approaches

| 方式 | 利点 | 代償・判断 |
|---|---|---|
| 接続・手動校正を先に単体で完成させ、動作調停と会話同期をつなぐ | iPhone とファームウェアの問題を先に切り分けられる。会話を動かさずに校正を検証できる | 段階ごとの結合試験が要る。前の提案に沿った採用方式 |
| BLE と会話同期を一度に組み込む | 最初から会話と首をまとめて試せる | 接続・生成・音声・動作のどこが原因か判別しにくい。今回は採らない |

BLE 実装は **CoreBluetooth を直接使い、細部を RobotLink 内に閉じ込める**。これは作り手の判断。AsyncBluetooth の追加も検討したが、独自プロトコルの保存照合、送信制御、世代管理は別途必要なため、今回は既存の Swift / SwiftUI と Apple の標準フレームワークで作る。新しいパッケージは追加しない。

## 3. 構成と責務

| 部分 | 責務 |
|---|---|
| `RobotProtocol` | 固定長の符号化・復号。角度は 0.1° の整数。GATT UUID、Status・Info・Calibration・Limits の型 |
| `CoreBluetoothRobotTransport` | 1 台へのスキャン・接続・サービス探索・Read/Write/Notify・送信可能通知。CoreBluetooth のオブジェクトを外へ出さない |
| `RobotLink` | 接続状態、暗号化が必要な Read を含む準備、1 Hz PING、再接続、接続世代、送信待ち、鮮度、保存トランザクション |
| `MotionCoordinator` | ツール＞追尾＞待機の調停、1 サイクル単位の直列実行、発話開始待ち、ターン予算、設定・校正の専有、世代の無効化 |
| `MoveHeadTool` | 引数の検証と予約。実機の完了を待たず短い受付結果を返す |
| `RobotSettingsModel` / 画面 | 接続先選択、状態とエラー、動きの強さ、待機微動、校正のドラフトと操作 |

`RobotLink`・`MotionCoordinator`・画面モデルは `@MainActor` で直列化する。パケットの値型は `Sendable`。CoreBluetooth は main queue で使う。delegate からの入口で実行キュー・接続元を検証し、Swift 6 の隔離を満たす。BLE の参照を別 actor に渡したり、BLE オブジェクト全体を `@unchecked Sendable` にしたりしない。

Transport と上位の境界は値型のイベントと操作にし、実機のないテストでは FakeTransport、Clock、乱数、保存先を差し替える。公開するメソッドの綴りと内部ファイルの細分化は実装計画で決めるが、以下の契約を変えない。

### 主な境界

- RobotLink: `start / selectDevice / suspend / resume`、スナップショット購読、期限付きの送信、特性の Read、校正のプレビュー・保存。
- MotionCoordinator: ターン開始・生成終了・発話開始・発話終了・失敗、ツール予約、前面状態、設定/校正の専有、任意の追尾入力。
- 校正の書き込み、動作コマンド、PING を別の呼び出し元から直接 Transport に流さない。送信の順序と失効判定は RobotLink が一元管理する。

## 4. 接続と通信

### 4.1 起動と接続先

Composition の生成だけでは CBCentralManager を作らず、権限要求・スキャン・接続・モーター操作をしない。初回は設定の「ロボット」で利用者が接続操作をしたときに開始する。保存済みの接続先がある場合は、会話画面への初回遷移と以後の前面復帰で再開する。BLE の準備を会話の preflight の必須条件にしない。

保存するのは選んだ peripheral の UUID と表示名、動きの強さ・待機微動の設定だけ。MAC を接続 ID にしない。未選択のロボットに自動で接続しない。

初回スキャンはサービス UUID で絞り、接続先一覧を出す。選択後はスキャンを止め、接続、必要なサービス・5 特性の探索、Info の確認を行う。プロトコルが 1 でなければ動作を許可せず、「対応していないロボットです」と表示する。

Status の Read は暗号化が必要で、ペアリングを開始する入口として使う。続けて Status の Notify、Calibration・Limits の Read を確認する。Command への応答なし書き込みでペアリングを試さない。OS の権限・認証失敗は原因別に表示し、アプリ内でボンド解除を自動実行しない。ロボットのペアリング窓が閉じている場合は、電源の入れ直しまたはシリアルの PAIR OPEN で開く手順を案内する。

### 4.2 状態と再接続

| 状態 | 表示・動作 |
|---|---|
| 未選択 | 接続先を選べる。会話は利用可 |
| Bluetooth 利用不可 / 権限なし | 原因と設定への案内。権限なしで再試行ループを回さない |
| 検索中 / 接続中 / 準備中 | 動作と校正を無効化する |
| 接続済み | Info・暗号化 Read・Notify の準備完了。Status を表示し、PING を開始 |
| 接続済み・復帰中 | 接続は成功しているが、RETURNING / MOVING / GESTURE の解消まで自動の動作開始を待つ |
| 未接続・再接続中 | 会話は継続。古い予約を破棄する |
| 利用者が接続解除 / 前面外 | PING と再接続を停止する。明示の再開まで接続し直さない |

再接続は保存済み UUID の取得を先に試し、見つからなければサービス UUID で再発見する。切断時から 2 秒間隔を目安に、重複しない接続試行を行う。1 回の試行は通常 5 秒以内に準備完了を目標とし、タイムアウトなら接続を取り消す。初回の OS 権限・ペアリング待ちは別の扱いとし、画面に待機とキャンセルを示す。

接続取消の終端 callback を待ってから同じ peripheral に再試行する。終端が来ない場合は manager を作り直して古い callback を隔離する。manager、接続、特性の世代を持ち、旧 manager、旧特性、旧読み取り・保存待ちからの結果を新しい接続に適用しない。

再接続時はファームウェアの安全復帰を PING で解除しようとしない。復帰中は待ち、動作可能になってから正面を確認して再開する。切断前のツール動作、MOVE、校正のプレビュー、保存要求は再生しない。

### 4.3 PING、鮮度、送信

- 接続の準備完了から切断・中断まで 1 Hz で PING を送る。設定や校正で会話を止めている間も継続する。
- 接続中でも Status が 1 秒以上届かなければ古い状態として新規要求・連続 MOVE 送信を止める。実行済みの動作を停止したとは扱わない。再 Read と新しい PING の seq の返却で確認し、2 秒以内に回復しなければ切断して通常の再接続へ戻す。
- `withoutResponse` は完了通知ではない。`canSendWriteWithoutResponse` と送信可能 callback に従い、待機中も接続世代・有効期限を確認する。1 コマンドを分割しない。
- 優先度は停止・中断処理、PING、排他的な校正処理、通常の動作。未送信の MOVE / 校正プレビューは種類ごとに最新 1 件へ置換する。通常の動作コマンドは無制限に蓄積しない。
- 実行可能になって RobotLink の送信待ちに入った動作は、300 ms を超えてから送らない。発話開始待ちや前サイクルの完了待ちは MotionCoordinator 内の予約であり、この送信待ち期限と区別する。待機・追尾 MOVE は各ストリームの最新値だけを最大 20 Hz で送る。
- GESTURE を受理したか不明なときに再送して二重実行しない。受理・完了は送信後の新しい Status に GESTURE / MOVING が立ち、その後下りたことで確認する。1 秒以内に開始を観測できなければ「開始を確認できない」として残りの動作を破棄する。
- 完了待ちの期限は予測時間に 2 秒を加え、最大 20 秒。期限切れなら動作待ちとキューを終了して再同期する。SAVE_CAL の同じ req での再送は §6 の別扱い。

## 5. 首の動作と会話の同期

### 5.1 ツールの予約とターンの寿命

`move_head(gesture, intensity, repeats)` の形を保つ。gesture は nod / shake / tilt / look_up / look_down / look_at_user / center、intensity は small / medium / large、repeats は 1〜3（省略 1）。未定義の文字列や範囲外は拒否して短い説明を返す。

Tool.call は実機の動作完了や、これから始まる発話を待たない。呼び出し時に接続・校正専有・ターン有効性・予約予算を検証し、「頷く動作を予約しました」「今は首が動かせません」「この返答の動作枠を超えるため追加しません」のような結果を即時に返す。予約結果を実行済みと表現しない。

返答の実行ごとに、音声入力・文字入力の両方で不変の MotionTurnID と世代を発行する。予約、発話開始通知、失敗・中断はその ID に結び付ける。セッションを再利用しても前のターンの予約を使わない。`ReplyPlaybackCoordinator.run` でターンスコープを設け、子タスクに伝える。Tool.call は明示のターンスコープがない場合に現在のターンを推測して使わず、予約を拒否する。

既存の `ReplyTraceContext` と同様に TaskLocal を使う案を第一候補とする。ただし SDK 境界での伝播は実装の最初の技術確認事項とし、ネットワークを使わない LanguageModelSession / fake executor の結合試験で確かめる。伝播を仮定したまま出荷せず、必要なら session client 内の明示的な実行スコープへ置き換える。どの場合も古いターンを新しいターンとして扱わない契約を優先する。

最初の `.speechStarted` でそのターンの予約を解放する。通知の重複で二度再生しない。既に発話開始済みのターンに追加で予約されたものは、同じ予算の中で順に実行する。読み上げが正常に終わっても、既に始まったサイクルと受け付けた予約は予算内で完了させる。生成も終わり、予約も実行中もなくなったらターンを閉じる。

発話開始は実行の最早時刻である。前のターンのサイクルをまだ実行中なら、その完走を優先し、新しい予約は後に実行する。この場合は発話から遅れることを受け入れ、待ち時間を別途記録する。

発話前の生成失敗・拒否・端末内モデルへの切り替えでは、その生成に属する予約を破棄する。成功していない Claude の予約を、代替モデルの「接続できません」の発話で解放しない。音声合成の失敗、明示の停止、新しい会話、バックグラウンド、接続先変更、切断では予約を失効させる。新しいターンが始まった場合、前の実行中サイクルは完了させ、未開始分は捨てる。新しいターンの動作はその後に始める。

### 5.2 4 秒目安の契約

- 予算は 1 ターンの自動のツール動作だけに適用し、校正や利用者の停止には適用しない。
- 1 回の repeats をファームウェアにまとめて渡さず、1 サイクルずつ直列化する。repeats=3 を 12 秒の見上げ 1 コマンドにして予算をすり抜けさせない。
- そのターンの最初の 1 サイクルは、約 4.1 秒の look でも受け付ける。既に始めたサイクルは、4 秒で STOP を送って切らない。
- 2 サイクル目以降は、完了した動作時間と開始予定分の予測時間の合計が 4 秒以内に収まるものだけを予約・開始する。中立への寄せとピッチ遅延も予測に含める。計算誤差による実測の超過は完走を優先し、その先を追加しない。
- 所要時間の予測はファームウェア §4.4 の基準時間・振幅・上限による伸長から求める。Swift 側でサーボの制御用 Planner を複製しない。予測は予算用で、完了判定は Status による。
- 例（既定上限の目安）: shake large の repeats=3 は 2.08 秒×2でも4秒を超えるため1回へ。nod large は1.52秒×2の2回まで。look large は1回。予測に寄せ時間が加われば回数をさらに抑える。

### 5.3 振幅と強さ

| gesture | small / medium / large | 指令 |
|---|---|---|
| nod | 5 / 10 / 15° | GESTURE 1、ピッチの波形 |
| shake | 8 / 15 / 25° | GESTURE 2、ヨーの波形 |
| tilt | 8 / 12 / 15° | GESTURE 3/4。左右を交互にし、最初は左（作り手の判断） |
| look_up / look_down | 8 / 14 / 20° | GESTURE 5/6 |
| center | 振幅なし | CENTER。repeats は1回扱い |
| look_at_user | サブ計画4の追尾入力が新鮮ならその方向、未実装・対象なしなら正面 | MOVE または CENTER。顔を検出したと偽らず、正面への予約と返す |

標準は実機比較に使った既定上限の yaw 120°/s・pitch 100°/s。控えめはその 0.5 倍（60 / 50）、活発は1.5倍をハード上限で制限（180 / 120）。ピッチの活発は上限のため1.2倍になる。これは FR-MOV-13 の暫定値を置き換える提案で、作り手の判断。

動きの強さは Limits の速度欄だけで適用し、角度欄は0（変更なし）とする。GESTURE の speed は100を基本とし、選んだ波形自体を変えない。強さの変更は実行中の動作を完了し静止した後に反映する。SET_LIMITS の適用は特性の Read で照合し、反映できなければ新しい強さを表示しない。起動・再接続後も選んだ強さを、静止を確認してから再適用する。

### 5.4 自動動作と優先順位

ツール＞追尾入力＞待機微動。サブ計画3では追尾の入力口のみを作り、カメラは動かさない。新鮮な追尾入力がなければ、追尾由来の動作をしない。追尾入力の有効時間・10秒の見失い復帰は、サブ計画4でカメラの時刻と結合して確定する。

待機微動は接続・前面・会話の待機中・設定外で、4〜10秒ごとに yaw ±3°、pitch ±2°以内。実機で「跳ねる感じがするのでゆっくりに」という利用者の指摘を受け、3〜4秒の滑らかな MOVE の目標列とし、最大20Hz、speed 10固定とする。ファームウェアのS字追従も含めて所要を実機で確認する。次の実装計画で Clock / 乱数を注入し、上限・間隔・中断をテストする。

発話確定時の小さい頷きは、正面付近ではピッチ0→−5°→0の短いMOVE列で約0.6秒を狙う。校正後など、開始時の姿勢がyaw ±3° / pitch ±2°の外なら列全体をspeed 10にし、通常速度で急に正面へ戻さない。この場合は低速の復帰を優先し、実際の頷きの約0.6秒完了は目標にしない。最短1秒の内蔵nodを誤って0.6秒と扱わない。ツールの発話開始が来たら自動動作の残りを破棄し、古いMOVEを後から送らない。通常の自律目標は yaw ±45°、pitch ±20°に制限する。

### 5.5 中断と復帰

通常の発話終了と、新しいターンへの切り替えはサイクルを完了させる。利用者の「停止」、音声・アプリの失敗、前面外への遷移、切断は完走より優先する。

設定を開くと自動の新規予約を停止する。開始済みのジェスチャは完了を待ち、校正の専有へ移る。「停止」ボタンは待たず STOP を送る。設定を閉じて会話に戻るときは、既存 coordinator の再開規則に合わせて自動動作を再開し、古い予約を再開しない。

一時的な inactive（権限・ペアリングなど）では新しい動作を止め、進行中の接続準備や必要なPINGは維持する。background ではPING・送信・再接続を止めて接続を取り消し、ファームウェアの切断・無通信復帰に任せる。STOPを先に送ってから切断すると中立復帰が止まるため、この経路では使わない。前面に戻ったら接続を再開する。

### 5.6 接続を保ったまま静止するときのPWM停止

PINGを継続するとファームウェアの無通信復帰は始まらないため、静止時のPWM停止はアプリが行う（ファームウェア設計 §4.5）。ただし実機でPWM停止・再開時に跳ねを確認したため、待機微動がオンの間は会話・設定画面ともPWMを維持し、次の微動までの間に停止しない。校正から設定を経て会話へ戻る際にも維持する。オフに切り替えてから、新鮮なStatusでMOVING/GESTUREがなく、ACTIVEのまま2秒連続して静止し、保存・強さの変更処理中でもなければ、`TORQUE 0`を1回送る。オンへ戻したら待機中の停止ticketを失効させる。RETURNING/RELAX_WAIT/IDLEには追加で送らない。明示停止とbackgroundでの切断・FW安全復帰は待機微動の設定にかかわらず優先する。

自動のTORQUE 0は利用者の停止とは区別し、動作より低い優先度で送る。静止を確認した操作世代を付け、新しい動作で未送信の停止を失効させる。送信直前にも静止と世代を確かめ、動き始めた直後に古いタイマーで止めない。PINGは継続し、次のMOVE/GESTURE/CENTER/SET_CALがファームウェアをACTIVEへ戻す。再開のためだけにTORQUE 1や不要な正面合わせを追加しない。実機の位置保持が続くこと、電源遮断や保持電流低減を保証する操作ではないことを区別する。

## 6. 校正

### 6.1 専有とプレビュー

校正画面は、動作中のジェスチャとMOVEが終わり、RETURNING中でなく、Calibration・Limitsを新しく読めた後に操作可能にする。それまでは「動作の終了を待っています」と表示する。途中でも停止はできる。

開始時の適用値を entry snapshot として保持する。左右・上下のオフセットは±20°・0.5°刻み、反転は軸ごとのToggle。変更は最新値にまとめて最大10Hzでプレビューし、送信中の値より古いプレビューを後から送らない。校正中は自動動作・ツール要求を許可しない。モーター位置はStatusの指令角であり、実測角と表示しない。

「正面」はCENTER。実機確認時の利用者の指摘により、校正画面の左右はロボットと向かい合って見た方向とする（左は負yaw、右は正yaw）。画面に向きの説明を添える。プロトコルの座標と自律動作の意味は変えない。「左/右/上/下端へ」は新しく読んだファームウェアの角度上限（最大±60°/±30°）を使い、通常の自律上限とは区別した明示の操作にする。低い固定speedで1方向ずつ実行する。一括の往復試験を自動で始めない。新しい方向を選べば前の待ち操作を置換し、停止は最優先。

反転やオフセットを、まだGESTURE中のファームウェアへ送らない。ファームウェアはジェスチャ中のSET_CALを受けると波形からPlannerへ連続的に引き継いで手動調整へ移るが、意図しないジェスチャの中断を避けるため、アプリの校正専有と静止待ちは維持する。途中の角度上限変更は波形標本の飽和を直接変えるため、同様に静止を待つ。

### 6.2 保存トランザクション

保存中はドラフト編集とほかの校正書き込みを止め、保存対象の値を固定する。手順:

1. 待機中の古いプレビューを破棄し、固定した意図値を SET_CAL で送る。
2. 最新のStatusのsave_seqと異なる1〜255のreqを選び、SAVE_CAL(req)を送る。
3. 送信後の新しいStatusで同じreqの結果を待つ。1秒で来なければ同じreqを再送し、計3回まで試す。
4. 同じreqに対するSAVE_ERROR=1は保存失敗。0ならCalibrationをReadする。
5. saved=1かつオフセット・反転が意図値と一致したときだけ「ロボットに保存済み」にする。
6. 値が違えばSET_CALから新しいreqでやり直す。全体のやり直しは2回まで。失敗時はドラフトを保ち、再試行を選べるようにする。

reqが255から1へ戻る場合、遅延した通知、途中の切断、NVS失敗、外部シリアルでの校正変更も成功と取り違えない。全体は接続世代と1つの保存操作IDで識別する。切断・画面終了・新しい操作で旧結果を無効化する。PINGは保存中も続ける。

### 6.3 戻す・閉じる・切断

「今回の変更を戻す」はentry snapshotの適用値をプレビューし直す。NVSへの保存はしない。画面を開いた時点で既に未保存だった値を、保存済みと扱わない。

新しい未保存変更がある状態で戻る場合は、保存するか、今回の変更を戻してから戻るかを選べるようにする。画面の構成は案01を使い、この離脱処理を補う。接続が切れた場合は操作を無効化し、戻せなかった変更があることを示す。再接続でドラフトや保存を自動再送せず、実際のCalibrationを読み直して利用者の操作を待つ。

プレビュー後にドラフトをentryと同じ値へ戻しても、ロボットへの復元を確認できたとは限らない。終了時は送信待ち・期限切れのプレビューを取り消し、entryの再適用とRead一致を確認してから閉じる。一度も編集していない場合は追加の読み書きを行わない。

## 7. 画面と既存アプリへの結合

画面案01は本設計のUI構成として利用者が確認済み。既存の設定の「ロボット」から接続画面へ進み、「中立と回転方向を調整」で校正画面へ進む。ロボットの選択一覧は接続画面の検索・接続先変更で開く。

接続画面は接続先・接続状態、動きの強さ、待機微動、校正への入口、FW版数・状態・指令角を出す。会話画面には「首と接続中」「首と未接続」「首を再接続中」の短い表示を加える。BLEの通知ごとにVoiceOverを読み上げず、接続状態が変わるときだけ通知する。

校正画面は左右に区分したFormを基本に、画面案のオフセット・反転・方向確認・停止・保存を実装する。Dynamic Typeが大きい場合は1列にしてスクロールできる。オフセットの数値、保存状態、接続失敗を色だけで伝えない。

`ConversationComposition` がRobotLink・MotionCoordinator・設定モデルを一度だけ組み立てる。既存のテスト・PreviewではNoopの首制御を既定にできる。AppRootView / ConversationAppCoordinator が前面状態・設定の開閉を伝える。

`ConversationToolProvider` はrememberにmove_headを加える拡張点として使う。記憶の書き込み口は今のセッション世代のまま保ち、首のためにClaudeセッションを毎ターン作り直さない。固定のtoolGuidanceに予約・発話同期・利用不可時の説明を追加し、会話のたびに可変の接続状態をinstructions前方へ差し込まない。

ReplyPlaybackCoordinatorと音声/文字のViewModel経路にターンと再生イベントを接続する。音声合成の実装自体にはBLEを入れない。代替モデルへの切り替えと生成失敗は、同じターンの古い動作を失効させる明示の通知を追加する。

NSBluetoothAlwaysUsageDescriptionには、首の接続・操作にBluetoothを使うことを日本語で記載する。バックグラウンドBluetoothモードは追加しない。権限を拒否された場合は首だけ無効化し、会話を続ける。

## 8. 性能・保存・観測

- 接続先・動きの設定は既存アプリと同じUserDefaultsの方式。音声、画像、会話本文、ツール引数の全文をBLE用ログに保存しない。
- 角度・フラグは画面へ最大5Hz程度で更新。ボタンや保存完了は状態変更で即時反映する。
- OSLogは接続世代、状態遷移、切断理由の分類、送信/開始/終了/保存確認の時刻だけを扱う。端末IDはログへ出さない。
- ほかのサイクルを実行中でなければ、発話開始から動作開始の目標は300ms以内。Tool.callからの時間には発話待ちを含むため、NFR-PERF-3は「予約が実行可能になってから首が動き始めるまで」に読み替える提案とする。ツールの予約受付時間、発話開始からの実測値、前サイクルの完走待ちはそれぞれ記録し、待ち時間を隠さない。
- 接続先を変える、明示停止する、バックグラウンドへ移る際に未送信の動作を残さない。待機タスク・購読・タイマーを所有者が終了し、再開しても多重化しない。

必須の自動テスト:

- 全9コマンドと4種のReadデータのgolden bytes。Statusの-12.3°が85 FFになることなど、既存の実装を正本に固定する。
- 接続取消後の成功callback、旧Notify、旧SAVE結果、Bluetoothオフ/権限拒否、サービス不一致、同じ接続先への再試行の非重複。
- 応答なし送信が詰まっている間のSTOP/PING/MOVE置換、期限切れ、再接続後に古い送信がないこと。
- 保存の部分落ち、同じreq再送、req折り返し、NVS失敗、saved=0、Read値不一致、保存中のドラフト固定。
- 音声/文字の両方で、発話前に動かず、開始通知が重複しても1回だけ動くこと。正常な発話終了後は完走すること。
- 発話前失敗・代替モデル・新しい会話・旧Tool.callの遅着で、予約が別ターンから解放されないこと。
- 1回4.1秒のlook、repeats=3の切り詰め、複数Tool.call、始めたサイクルの完走、新しいターンへの切り替え。
- 校正待ちと専有、終了/切断での遅いプレビューの破棄、戻す時の元から未保存だった値。
- 待機微動の振幅・時間・間隔・停止と、強さ変更の静止待ち。待機微動オンでは設定滞在中もPWMを維持し、オフ時は静止2秒後にTORQUE 0を送ること。オンへの切り替えや新しい動作で古い停止が失効し、BLE送信直前にも最新の設定を確かめること。既存の会話・音声・記憶の回帰試験。

実機はシミュレーターでは代用しない。首が動く試験は利用者在席時だけ行う。設計・テスト・ビルドのためにスキャン、書き込み、リセット、モーター指令を自動で実施しない。

実機受入: iPhoneでのペアリングとボンド済み再接続（通常5秒以内）、2台目centralによる60秒窓外の拒否（既存T-FW-9の残り）、接続中のPING継続、動作中の切断と復帰、再接続での予約非再生、校正の保存と再起動後の保持、7種×3強度、発話開始との時間差、方向別の端確認。未確認の最大可動域は低速・1方向ずつ利用者が確認する。
