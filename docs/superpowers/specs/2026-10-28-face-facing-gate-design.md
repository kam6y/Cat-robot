# 顔の向きによる追尾条件

## 目的と範囲

利用者の「一旦、顔の向きだけを条件に加える形で実装してみて」に従い、猫側をおおむね向いている顔だけを首の追尾対象にする。

## 方式

現在のAVCaptureSession + Visionを継続し、VNFaceObservationのyaw/pitchを利用する方式を採用する。視線推定を行うARKit案はカメラ構成・電力検証の範囲が広く、今回は利用者が顔の向きだけを選択した。顔の中心位置だけで追尾する旧方式へはフォールバックしない。

- Vision revision 3から、向きを正規化した非反転画像に対するyaw/pitchをラジアンで取り込む。
- 候補条件: 保存済みの `trackingYawCorrection` を c 度とすると、Vision yawが `[-c - 30, -c + 30]` 度、pitchが `[-25, 25]` 度の範囲にあること。どちらも端点を含む。上下の判定はカメラ正面を中心とし、c では動かさない。両角度が存在し有限値であることを要求する。既定値8.5度の場合、yawの範囲は `[-38.5, 21.5]` 度。
- 左右判定の中心を -c 度にする理由: カメラは利用者から見て画面の左に固定されている。カメラのレンズから画面中心へ顔を向けると、顔は非反転画像の左を向き、Vision yawは負になる。
- 候補を絞った後に、既存の「画面中央に近い顔、同距離なら大きい顔、座標順」を適用する。複数人で中央の横顔が手前にあっても、こちら向きの別の顔を選べる。
- 設定値は度、Visionはラジアンであり、上下限を度で作ってからラジアンへ変換して閉区間で比較する。補正値が非数または0〜20度の範囲外なら候補なしとする。候補選択と投影の両方に同じ補正値を明示的に渡す。追尾先そのものの投影、首の姿勢、速度・角度制限は維持する。
- 設定画面で補正を変更した場合は既存の停止・撮影世代の切替に従い、会話へ戻った後の新しい画像から追尾先と判定中心の両方へ反映する。
- 候補がいないフレームは従来の顔喪失と同じ扱い。新しい追尾目標を発行せず、追尾目標を作れた最後のこちら向きの顔の撮影時刻から10秒で一度だけ正面へ戻る。その後、待機中は既存設定に従って待機微動を再開できる。
- 新しい方向候補が得られれば、既存の画像鮮度・姿勢時刻の検査後に再開する。向いていない顔や角度不明の顔では10秒の期限を更新しない。既存どおり、こちら向きの新鮮な画像が姿勢時刻の補間待ちである間は、期限を更新せずに復帰判断を一時的に保留する。その画像が失効すれば元の期限で判断する。後から向いていない顔のフレームが来た場合は、この保留画像も直ちに捨てる。

判定幅を決めるまでの経緯（一時的に左右±20度・上下±15度へ狭めた試用を含む）は[検証記録](../../validation/2026-10-28-face-facing-gate.md)にある。

## 制約と限界

撮影は設定3fps、画像640×480以下のまま。追加の画像解析リクエスト・タイマー・ネットワーク送信・保存画像・設定項目を増やさない。lookの撮影、会話音声、熱停止、背景停止、世代検査、首の速度・角度制限を維持する。

これは顔の正面性による近似であり、目の視線や猫の目への注視を保証しない。カメラと画面中心の位置差、会話距離、顔の画面内位置による見え方の違いがあるため、閾値は実機での体感に合わせて調整する。状態や人物識別を持たない単純な角度条件なので、閾値近くの小さな動きで追尾と保持が切り替わることがある。首は顔が対象から外れても直ちに正面へ跳ねず、現在の保持・10秒復帰経路を使う。

## 検証

角度不明、NaN/Infinity、左右両側、上下両側、閾値の内外、補正値ごとの判定中心、複数顔の候補選択、角度不明時の10秒期限、顔の再取得、設定変更後の判定中心の更新、未処理の姿勢待ちフレームが横向きフレームに置き換わる場合を検証する。既存のカメラ共有・停止・熱・待機微動の関連テストとproject生成チェックを実行する。実機ビルド・インストール後の物理的な向き判定の精度と発熱は、実際の人の顔で確認する必要がある。変更前の基準テストと各段階の実行結果は[検証記録](../../validation/2026-10-28-face-facing-gate.md)に残す。
